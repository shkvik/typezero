# TypeZero для VS Code

Ошибки по мере набора, подсветка, форматирование и значок программ на typezero — файлов `.tz`. В строке состояния VS Code язык называется
TypeZero. Синтаксис у tz тот же, что у TypeScript, поэтому
грамматика — TypeScript, которая есть в VS Code: язык `tz` подключает её
([syntaxes/tz.tmLanguage.json](syntaxes/tz.tmLanguage.json)). Скобки, комментарии и отступы —
как у TypeScript ([language-configuration.json](language-configuration.json) — копия файла
VS Code, MIT).

## Значок

У файлов `.tz` в проводнике и на вкладках свой значок — буквы «TZ» ([icons](icons): светлая и
тёмная темы). Это значок языка (`icon` в `package.json`): тема значков, у которой нет своего
для tz (Seti, что идёт с VS Code, и большинство других), берёт его.

## Форматирование

Alt+Shift+F (Format Document) и Format Selection форматируют файл `.tz` Prettier'ом
([format.js](format.js)): синтаксис у tz тот же, что у TypeScript, поэтому Prettier читает файл
как TypeScript. Настройки — его по умолчанию: отступ 2 пробела, точки с запятой, двойные
кавычки, строки до 80 знаков; концы строк (`\r\n` или `\n`) остаются, как в файле. Расширение
делает себя форматтером файлов `.tz` по умолчанию и ставит им отступ 2 пробела без угадывания по
файлу (`editor.detectIndentation`); при сохранении файл не форматируется. Если в файле
синтаксическая ошибка, он остаётся как есть, а VS Code показывает ошибку со строкой и столбцом.

Prettier лежит в [third_party/prettier](../../third_party/prettier/README.md); `install.ps1`
копирует его в расширение.

## Ошибки

Ошибки и предупреждения компилятора подчёркиваются в файле и видны в Problems, пока вы набираете
текст, — и несохранённый текст тоже. Их показывает языковой сервер `tz lsp`
([docs/lsp.md](../../docs/lsp.md)); клиент — [server.js](server.js) с `vscode-languageclient`
([third_party/vscode-languageclient](../../third_party/vscode-languageclient/README.md)).

- После паузы в наборе (0,3 с) компилятор проверяет программу целиком, без сборки: файл,
  который импортирует `"main"` ближайшего вверх `tz.json`, — вместе с этим `main`; файл без
  `tz.json` или который `main` не импортирует, — как отдельную программу. Ошибки модулей, которые
  не открыты, тоже приходят.
- Какой `tz`: настройка `tz.path`, иначе `tz` из `PATH`, иначе `build/dev/bin/tz.exe` открытой
  папки (репозиторий tz). Сервер запускается из копии `tz` во временном каталоге, поэтому сборка
  может заменить `tz.exe`, пока редактор открыт; когда `tz.exe` меняется, сервер перезапускается
  с новой копией. Команда `TypeZero: Restart the Language Server` перезапускает его вручную,
  журнал — в Output, канал TypeZero.

## Наведение, переход, дополнение, переименование

Тот же сервер отвечает по тому, что узнала последняя проверка: классы (`Server`, `Response`,
`URL`), функции, методы, поля и переменные окрашиваются по смыслу; наведение показывает сигнатуру
(с выведенными типами) или тип имени, F12 — переход к определению (во встроенный модуль tz —
его копия рядом с `tz.exe`), Shift+F12 — все ссылки, после точки — поля и методы типа, F2 —
переименование всех мест (встроенное не переименовывается).

## Чего нет

Разбора, который понимает недописанный код, нет: пока текст не разбирается, ответы идут из
последней удачной проверки. Объявления для проверки TypeScript лежат рядом с `tz.exe`, в `types`
([docs/modules.md](../../docs/modules.md), раздел 6).

## Установка

Копией в каталог расширений пользователя:

```
powershell -ExecutionPolicy Bypass -File editors\vscode\install.ps1
```

После этого — `Developer: Reload Window`. После правки расширения команду повторяют.
