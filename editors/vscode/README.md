# TypeZero для VS Code

Ошибки по мере набора, подсветка, форматирование и значок программ на typezero — файлов `.tz`. В строке состояния VS Code язык называется
TypeZero. Синтаксис у tz тот же, что у TypeScript, поэтому
грамматика — TypeScript, которая есть в VS Code: язык `tz` подключает её
([syntaxes/tz.tmLanguage.json](syntaxes/tz.tmLanguage.json)). Скобки, комментарии и отступы —
как у TypeScript ([language-configuration.json](language-configuration.json) — копия файла
VS Code, MIT).

## Значок

У файлов `.tz` в проводнике и на вкладках свой значок — буквы «TZ» ([icons](icons): светлая и
тёмная темы). Это значок языка (`icon` в `package.json`): тема значков, у которой нет своего
для tz (Seti, что идёт с VS Code, и большинство других), берёт его.

## Форматирование

Alt+Shift+F (Format Document) и Format Selection форматируют файл `.tz` Prettier'ом
([format.js](format.js)): синтаксис у tz тот же, что у TypeScript, поэтому Prettier читает файл
как TypeScript; `partial` перед `class` и `readonly` перед методом, которых в TypeScript нет, он
видит как комментарий той же длины. Настройки — его по умолчанию: отступ 2 пробела, точки с запятой, двойные
кавычки, строки до 80 знаков; концы строк (`\r\n` или `\n`) остаются, как в файле. Расширение
делает себя форматтером файлов `.tz` по умолчанию и ставит им отступ 2 пробела без угадывания по
файлу (`editor.detectIndentation`); при сохранении файл не форматируется. Если в файле
синтаксическая ошибка, он остаётся как есть, а VS Code показывает ошибку со строкой и столбцом.

Prettier лежит в [third_party/prettier](../../third_party/prettier/README.md); `install.ps1`
копирует его в расширение.

## Ошибки

Ошибки компилятора подчёркиваются в файле и видны в Problems, пока вы набираете текст, — и
несохранённый текст тоже. Их показывает компилятор tz, написанный на tz (`self/`): C++-компилятор
`tz lsp` не знает правил владения ([docs/ownership.md](../../docs/ownership.md)) и считал бы их
ошибками, поэтому его ошибки не показываются, пока `tzparse` найден. Код — [check.js](check.js).

- Открытый файл проверяется как отдельная программа: сам файл и то, что он импортирует, командой
  `tzparse types <файл> --ownership --quiet`. Часть `partial class` импортирует свой класс, поэтому
  проверяется вместе со всеми частями. Показываются ошибки этого файла; ошибки модулей, которые он
  импортирует, видны, когда открыт их файл. Файлы объявлений (`.d.tz`) и библиотека репозитория tz
  (`library/`) не проверяются: они описывают то, что компилятор делает сам.
- Кроме ошибок — подсказки проверки владения: параметр можно взять как `Read<…>`, метод можно
  пометить `readonly`. VS Code показывает их точками под именем.
- Несохранённый текст открытых файлов уходит компилятору через `--overlay <файл> <копия>`: копия —
  во временном каталоге `tz-check`.
- Файл проверяется при открытии, после паузы в наборе (0,4 с) и при сохранении; сохранение
  проверяет и остальные открытые файлы — то, что они импортируют, могло измениться. Новая проверка
  файла останавливает старую; одновременно идут не больше двух проверок. Пока проверка идёт, в
  строке состояния крутится значок `tz`. Журнал — в Output, канал TypeZero Check.
- Какой `tzparse`: настройка `tz.selfPath`, иначе `build/self/tzparse.exe` открытой папки
  (репозиторий tz). Рядом с ним лежат `LLVM-C.dll` и `lib/` — библиотека. Туда кладёт сборку self
  скрипт `tmp/selfhost/tools/native/editor.sh <каталог сборки>`; на время проверки файл занят,
  поэтому скрипт пробует скопировать несколько раз.

## Наведение, переход, дополнение, переименование

Отвечает языковой сервер `tz lsp` ([docs/lsp.md](../../docs/lsp.md)); клиент — [server.js](server.js)
с `vscode-languageclient` ([third_party/vscode-languageclient](../../third_party/vscode-languageclient/README.md)).
Какой `tz`: настройка `tz.path`, иначе `tz` из `PATH`, иначе `build/dev/bin/tz.exe` открытой папки.
Сервер запускается из копии `tz` во временном каталоге и перезапускается, когда `tz.exe` меняется;
команда `TypeZero: Restart the Language Server` перезапускает его вручную, журнал — в Output, канал
TypeZero. Сервер — C++-компилятор, который не знает правил владения: в коде с `Read<…>`, `Cell<…>`,
`readonly`-методами его ответы могут быть неточны.

Сервер отвечает по тому, что узнала последняя проверка: классы (`Server`, `Response`,
`URL`), функции, методы, поля и переменные окрашиваются по смыслу; наведение показывает сигнатуру
(с выведенными типами) или тип имени, F12 — переход к определению (во встроенный модуль tz —
его копия рядом с `tz.exe`), Shift+F12 — все ссылки, после точки — поля и методы типа, F2 —
переименование всех мест (встроенное не переименовывается).

## Отладка

F5 на открытом файле `.tz` собирает его `tz build --debug` во временный каталог
(`%TEMP%\tz-debug`) и запускает под отладчиком расширения C/C++ от Microsoft
(`ms-vscode.cpptools`, тип `cppvsdbg`; без него расширение скажет, что его нужно поставить).
Точки останова ставятся в файлах `.tz`, шаги идут по строкам `.tz`, в Variables и Watch — переменные
со значениями: строки текстом, массивы и `Map` элементами, объекты полями, `Result` как `Ok(…)` /
`Err(…)` ([docs/debug.md](../../docs/debug.md)). Аргументы, окружение и рабочий каталог — в
launch.json, конфигурация типа `tz` (`program`, `args`, `env`, `cwd`, `stopAtEntry`); ошибки сборки
— в Output, канал TypeZero Debug. Код — [debug.js](debug.js).

## Чего нет

Разбора, который понимает недописанный код, нет: пока текст не разбирается, ответы идут из
последней удачной проверки. Объявления для проверки TypeScript лежат рядом с `tz.exe`, в `types`
([docs/modules.md](../../docs/modules.md), раздел 6).

## Установка

Копией в каталог расширений пользователя:

```
powershell -ExecutionPolicy Bypass -File editors\vscode\install.ps1
```

После этого — `Developer: Reload Window`. После правки расширения команду повторяют.
