# Модули

Решения, принятые 23 октября 2026 года. Шаги 1–3 плана сделаны 24 октября (`embedBytes` — вместе с
байтами), шаг 4 — 25 октября. 25 октября решено, что файлы tz называются `.tz` (раздел 2);
26 октября — что разбор JSON отдаёт `Result` ([errors.md](errors.md)), а числа из `Json`
переводят явными методами ([numbers.md](numbers.md)); подробности — в конце, в разделе «План
реализации».

## Коротко

- Файлы программ на tz — `.tz`: `main.tz`, `math.tz`. Файлы `.ts` и `.js` tz не собирает.
- Импорт — одной формой: `import { a, b as c } from "./x"`. Импорта по умолчанию,
  `export default`, `import * as`, `import "./x"` и слова `type` в импорте нет.
- Экспорт: `export` перед объявлением, `export { a, b as c }`, `export { a } from "./x"`,
  `export * from "./x"`.
- `as` есть только в `import` и `export` — как переименование. Оператора `as` нет.
- Циклические импорты разрешены. Ошибка компиляции — только если модуль при загрузке читает
  ещё не заданную переменную другого модуля (в node это `ReferenceError` при запуске).
- Пакеты — по имени (`import { z } from "zod"`), из JSR и git: [packages.md](packages.md).
- Файлы данных вшиваются в exe: `embedJson(путь)`, `embedText(путь)`. У JSON свой тип `Json`;
  `null` бывает только в нём.

## 1. Импорт и экспорт

```ts
// math.tz
export const PI = 3.14159
export function add(a: number, b: number) { return a + b }
function helper() { ... }              // без export — видно только внутри math.tz

// geometry/index.tz — «витрина» каталога
export { area } from "./circle"        // реэкспорт по имени
export * from "./square"               // реэкспорт всего, что экспортирует square.tz

// main.tz
import { add, PI } from "./math"
import { add as plus } from "./math"   // переименование
import { area, Circle } from "./geometry"   // типы импортируются так же, как значения
```

- **Импортированное только читают**, но изменения видны, как в JS:
  `import { counter, increment } from "./state"` — после `increment()` `counter` уже другой;
  `counter = 5` — ошибка.
- **`as`** — только переименование в фигурных скобках `import` и `export`
  (`import { add as plus }`, `export { area as circleArea }`). Это не приведение типа:
  оператора `as` в языке нет.
- **`export *`**: если два файла под звёздочками экспортируют одно имя — ошибка компиляции, как
  в tsc.
- **Ошибки с подсказкой** на остальные формы:
  - `import square from "./math"` и `export default` → экспортировать и импортировать по
    имени;
  - `import * as geo from "./geometry"` → перечислить нужные имена;
  - `import "./x"` (ради побочных действий) → импортировать то, что нужно, по имени;
  - `import type { T }` и `import { type T }` → писать без `type`.
- **`namespace` из TS** (`namespace Foo { ... }`) нет — это старая замена модулям; ошибка с
  подсказкой вынести в отдельный файл. `declare module`, `declare global`, `/// <reference>`,
  `require` и динамического `import()` тоже нет.

## 2. Файлы и пути

- **Файлы tz — `.tz`** (решено 25 октября). Синтаксис тот же, что у TypeScript, но язык свой.
  Скрипт на TS становится программой на tz, когда его переименовывают в `.tz` и правят то, что
  tz не принимает; библиотеку на TS переносит `tz port` ([packages.md](packages.md)). Пакеты для
  tz — тоже файлы `.tz`.
- `"./math"` и `"./math.tz"` — это `math.tz`.
- `"./math.ts"`, `"./math.js"` (так пишут в TS для node) и другие расширения TS и JS — ошибка с
  подсказкой: `the files of tz end in .tz: import './math' or './math.tz'`. Если рядом лежит
  `math.ts`, подсказка предлагает переименовать его; то же у `"./math"`, когда есть только
  `math.ts`. `tz build main.ts` — ошибка `rename it to main.tz`.
- Каталог — его `index.tz`: `"./geometry"` → `geometry/index.tz`.
- Пути только относительные (`./`, `../`). Имя без точки (`"zod"`) — пакет
  ([packages.md](packages.md)); `node:fs`, `tz:io` — встроенная библиотека ([io.md](io.md)).

## 3. Сборка и порядок загрузки

- `tz build main.tz` сам находит все файлы по импортам; на выходе — один exe. Экспорты, которые
  никто не использует, в exe не попадают.
- Порядок загрузки — как в JS: сначала то, что модуль импортирует (по порядку импортов), потом
  он сам; каждый модуль — один раз. Код верхнего уровня выполняется при загрузке модуля.
- Классы, функции и типы готовы ещё при компиляции, поэтому от порядка загрузки не зависят: в
  отличие от node, `class Circle extends Shape` работает при любом порядке импортов.

## 4. Циклические импорты

Цикл (`a.tz` импортирует `b.tz`, `b.tz` — `a.tz`, прямо или через другие файлы) разрешён: так
пишут типы, которые ссылаются друг на друга, взаимно рекурсивные функции в разных файлах,
модели данных с отношениями.

Ошибка — только если код, который выполняется при загрузке модуля (не внутри функции), читает
переменную другого модуля, которая к этому моменту ещё не задана, — прямо или через вызванную
функцию. Пример: `main.tz` импортирует `a.tz`, `a.tz` первой строкой импортирует `b.tz`, значит,
`b.tz` выполняется целиком раньше `a.tz`:

```ts
// b.tz
import { aName, getA } from "./a"
export const bSeesA = "b видит " + aName   // ошибка
export const bCallsA = getA()              // ошибка: getA читает aName
export function bLater() { return aName }  // ок: при вызове всё уже загружено
```

```
b.tz читает aName из a.tz при загрузке, но a.tz в этот момент ещё не загружен:
main.tz → a.tz → b.tz → (a.tz уже начат). Вычисли это внутри функции или перенеси aName
туда, где нет цикла.
```

Какой из файлов окажется «виноват», зависит от порядка импортов: если в `main.tz` поменять их
местами, ошибка переедет в `a.tz`. Поэтому сообщение показывает всю цепочку. Внутри одного
файла такая проверка уже есть: вызов функции с верхнего уровня раньше, чем объявлена глобальная
переменная, которую она читает, — ошибка.

## 5. Файлы данных и JSON

**Вшить файл в exe:**

```ts
const config = embedJson("./config.json")   // Json; синтаксис проверяется при компиляции
const page = embedText("./page.html")       // string
```

Путь — только строка-константа, относительно файла с вызовом: файл читается при компиляции, а
не при запуске (как `//go:embed` в Go, `include_str!` в Rust). Exe не требует файлов рядом.
Двоичные файлы — `embedBytes` ([bytes.md](bytes.md)). Настройки, которые меняют без
пересборки, читаются при запуске — это ввод-вывод.

**Тип `Json`** — встроенный:

```ts
type Json = null | boolean | number | string | Json[] | { [key: string]: Json }
```

- `JSON.parse(text)` возвращает `Result<Json, JsonError>` (в TS — `any`, а `any` у нас нет).
  Синтаксическая ошибка — `Err` с местом в тексте.
- Числа в `Json` — `double` (JSON не различает целые и дробные, а объединение `int | double`
  запрещено); в `int` переводят явно: `Math.trunc(port).toInt()` с доказательством, что влезает
  ([numbers.md](numbers.md)), — или сразу `JSON.parse<Config>` с полем `port: int`: тогда
  целое и диапазон проверяет сгенерированный разбор.
- **`null` бывает только в значениях `Json`.** `{"phone": null}` даёт `j["phone"] == null`,
  а отсутствующий ключ — `undefined`; `JSON.stringify(j)` выдаёт исходный текст без потерь. Во
  всём остальном языке «ничего» одно — `undefined`: `let x: string | null` — ошибка с
  подсказкой. Сравнивать с `null` можно только `Json`. `typeof null` — `"object"`, как в JS.
- `JSON.stringify` своего объекта пропускает поля со значением `undefined`, как JS. Нужен
  `null` в выводе — собрать `Json` явно: `const patch: Json = { phone: null }`.
- **Перевод `Json` в свои типы пишет компилятор:** `JSON.parse<Config>(text)` или
  `fromJson<Config>(j)` проверяет каждое поле и строит объект; результат — `Result`, `Err` с
  путём до поля ([narrowing.md](narrowing.md), раздел 3). Руками тоже можно — проверками и
  сужением.

## 6. Редактор

Файлы `.tz` VS Code сам не знает. Расширение [editors/vscode](../editors/vscode/README.md)
добавляет язык `tz`: подсветку грамматикой TypeScript, которая есть в VS Code, комментарии,
скобки и отступы как у TS. Ставится копией в каталог расширений
(`editors\vscode\install.ps1`).

- **Форматирование** — Prettier в расширении ([third_party/prettier](../third_party/prettier/README.md)):
  синтаксис у tz тот же, что у TypeScript, и Prettier читает файл `.tz` как TypeScript. Его
  настройки по умолчанию: отступ 2 пробела, точки с запятой, двойные кавычки, строки до 80
  знаков; концы строк остаются, как в файле. Только по команде (Alt+Shift+F, Format Selection),
  не при сохранении. Тест `tests/cli/format.cmake` проверяет, что Prettier разбирает все файлы
  `.tz` репозитория, кроме `tests/errors`.
- **Проверок нет.** Проверки типов, подсказок и перехода к определению в редакторе нет —
  ошибки показывает `tz build`. Их даст свой языковой сервер или плагин tsserver, который
  отдаёт файлы `.tz` проверке TypeScript.
- **Для плагина всё готово** рядом с tz, в `types/`: настройки tsc для программ tz,
  `@types/node` (node 24) и `tz.d.ts` ([editors/types](../editors/types/tz.d.ts)) —
  то, что в tz есть без импорта: `int`, `long`, `double`, `decimal` с методами, `Json`,
  `JSON.parse<T>`, `fromJson`, `embedJson`, `embedText`, `embedBytes`, `Result` (свой, без
  neverthrow), `SystemError`, `ExecSyncError`, `Constructor`, `ConstructorArgs`,
  `MethodDescriptor`, `Reflect.defineMetadata` и `getMetadata`, `Timeout`, типы Web Crypto, — и
  модули `"tz:io"` и `"tz:http"`. Тест `tests/cli/types.cmake` проверяет их TypeScript из
  VS Code на копиях программ с расширением `.ts`. После переделки ошибок и чисел (26 октября)
  объявления надо обновить: числа из [numbers.md](numbers.md) (`int8` … `uint64`, `Bit`,
  `Bit.Wrap32`, методы `toInt32()` и другие, без `long`), `node:fs` и остальное с `Result`
  вместо исключений, `SystemError` — тип объекта. `Result` уже свой (26 октября).
- **Настройки tsc.** Каждый файл — модуль (`moduleDetection: "force"`), импорты как в tz, DOM
  нет, `strict` без `noImplicitAny` (tz выводит типы параметров из вызовов), декораторы как в tz
  (`experimentalDecorators`). Где tz знает больше, объявление мягче: для tsc целые типы и
  `decimal` — `number`, значение метаданных — `any`, как в пакете reflect-metadata.
- **Замер** на 332 программах `tests/run`, пока они были `.ts` и tsc их проверял: с его
  настройками по умолчанию ошибки были в 302 программах, всего 3813; с настройками и
  объявлениями tz — в 69 программах, 299 ошибок. Остались места, где tsc строже tz: перегрузки с
  телом у каждого варианта ([overloads.md](overloads.md)), чтение полей `Json` без проверки,
  `onabort = undefined` (в tz нет `null`), члены, добавленные подменой класса, вычитание дат.
