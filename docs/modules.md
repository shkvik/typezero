# Модули

Решения, принятые 23 октября 2026 года. Шаги 1–3 плана сделаны 24 октября (`embedBytes` — вместе с
байтами); что осталось — в конце, в разделе «План реализации».

## Коротко

- Импорт — одной формой: `import { a, b as c } from "./x"`. Импорта по умолчанию,
  `export default`, `import * as`, `import "./x"` и слова `type` в импорте нет.
- Экспорт: `export` перед объявлением, `export { a, b as c }`, `export { a } from "./x"`,
  `export * from "./x"`.
- `as` есть только в `import` и `export` — как переименование. Оператора `as` нет.
- Циклические импорты разрешены. Ошибка компиляции — только если модуль при загрузке читает
  ещё не заданную переменную другого модуля (в node это `ReferenceError` при запуске).
- Пакеты — по имени (`import { z } from "zod"`), из JSR и git: [packages.md](packages.md).
- Файлы данных вшиваются в exe: `embedJson(путь)`, `embedText(путь)`. У JSON свой тип `Json`;
  `null` бывает только в нём.

## 1. Импорт и экспорт

```ts
// math.ts
export const PI = 3.14159
export function add(a: number, b: number) { return a + b }
function helper() { ... }              // без export — видно только внутри math.ts

// geometry/index.ts — «витрина» каталога
export { area } from "./circle"        // реэкспорт по имени
export * from "./square"               // реэкспорт всего, что экспортирует square.ts

// main.ts
import { add, PI } from "./math"
import { add as plus } from "./math"   // переименование
import { area, Circle } from "./geometry"   // типы импортируются так же, как значения
```

- **Импортированное только читают**, но изменения видны, как в JS:
  `import { counter, increment } from "./state"` — после `increment()` `counter` уже другой;
  `counter = 5` — ошибка.
- **`as`** — только переименование в фигурных скобках `import` и `export`
  (`import { add as plus }`, `export { area as circleArea }`). Это не приведение типа:
  оператора `as` в языке нет.
- **`export *`**: если два файла под звёздочками экспортируют одно имя — ошибка компиляции, как
  в tsc.
- **Ошибки с подсказкой** на остальные формы:
  - `import square from "./math"` и `export default` → экспортировать и импортировать по
    имени;
  - `import * as geo from "./geometry"` → перечислить нужные имена;
  - `import "./x"` (ради побочных действий) → импортировать то, что нужно, по имени;
  - `import type { T }` и `import { type T }` → писать без `type`.
- **`namespace` из TS** (`namespace Foo { ... }`) нет — это старая замена модулям; ошибка с
  подсказкой вынести в отдельный файл. `declare module`, `declare global`, `/// <reference>`,
  `require` и динамического `import()` тоже нет.

## 2. Пути

- `"./math"`, `"./math.ts"` и `"./math.js"` (так пишут в TS для node) — всё это `math.ts`.
- Каталог — его `index.ts`: `"./geometry"` → `geometry/index.ts`.
- Пути только относительные (`./`, `../`). Имя без точки (`"zod"`) — пакет
  ([packages.md](packages.md)); `node:fs`, `tz:io` — встроенная библиотека ([io.md](io.md)).

## 3. Сборка и порядок загрузки

- `tz build main.ts` сам находит все файлы по импортам; на выходе — один exe. Экспорты, которые
  никто не использует, в exe не попадают.
- Порядок загрузки — как в JS: сначала то, что модуль импортирует (по порядку импортов), потом
  он сам; каждый модуль — один раз. Код верхнего уровня выполняется при загрузке модуля.
- Классы, функции и типы готовы ещё при компиляции, поэтому от порядка загрузки не зависят: в
  отличие от node, `class Circle extends Shape` работает при любом порядке импортов.

## 4. Циклические импорты

Цикл (`a.ts` импортирует `b.ts`, `b.ts` — `a.ts`, прямо или через другие файлы) разрешён: так
пишут типы, которые ссылаются друг на друга, взаимно рекурсивные функции в разных файлах,
модели данных с отношениями.

Ошибка — только если код, который выполняется при загрузке модуля (не внутри функции), читает
переменную другого модуля, которая к этому моменту ещё не задана, — прямо или через вызванную
функцию. Пример: `main.ts` импортирует `a.ts`, `a.ts` первой строкой импортирует `b.ts`, значит,
`b.ts` выполняется целиком раньше `a.ts`:

```ts
// b.ts
import { aName, getA } from "./a"
export const bSeesA = "b видит " + aName   // ошибка
export const bCallsA = getA()              // ошибка: getA читает aName
export function bLater() { return aName }  // ок: при вызове всё уже загружено
```

```
b.ts читает aName из a.ts при загрузке, но a.ts в этот момент ещё не загружен:
main.ts → a.ts → b.ts → (a.ts уже начат). Вычисли это внутри функции или перенеси aName
туда, где нет цикла.
```

Какой из файлов окажется «виноват», зависит от порядка импортов: если в `main.ts` поменять их
местами, ошибка переедет в `a.ts`. Поэтому сообщение показывает всю цепочку. Внутри одного
файла такая проверка уже есть: вызов функции с верхнего уровня раньше, чем объявлена глобальная
переменная, которую она читает, — ошибка.

## 5. Файлы данных и JSON

**Вшить файл в exe:**

```ts
const config = embedJson("./config.json")   // Json; синтаксис проверяется при компиляции
const page = embedText("./page.html")       // string
```

Путь — только строка-константа, относительно файла с вызовом: файл читается при компиляции, а
не при запуске (как `//go:embed` в Go, `include_str!` в Rust). Exe не требует файлов рядом.
Двоичные файлы — `embedBytes` ([bytes.md](bytes.md)). Настройки, которые меняют без
пересборки, читаются при запуске — это ввод-вывод.

**Тип `Json`** — встроенный:

```ts
type Json = null | boolean | number | string | Json[] | { [key: string]: Json }
```

- `JSON.parse(text)` возвращает `Json` (в TS — `any`, а `any` у нас нет). Синтаксическая
  ошибка — исключение `SyntaxError`.
- Числа в `Json` — `double` (JSON не различает целые и дробные, а объединение `int | double`
  запрещено); в `int` переводит программист (`port | 0`).
- **`null` бывает только в значениях `Json`.** `{"phone": null}` даёт `j["phone"] == null`,
  а отсутствующий ключ — `undefined`; `JSON.stringify(j)` выдаёт исходный текст без потерь. Во
  всём остальном языке «ничего» одно — `undefined`: `let x: string | null` — ошибка с
  подсказкой. Сравнивать с `null` можно только `Json`. `typeof null` — `"object"`, как в JS.
- `JSON.stringify` своего объекта пропускает поля со значением `undefined`, как JS. Нужен
  `null` в выводе — собрать `Json` явно: `const patch: Json = { phone: null }`.
- **Перевод `Json` в свои типы пишет компилятор:** `JSON.parse<Config>(text)` или
  `fromJson<Config>(j)` проверяет каждое поле и строит объект, ошибка — `TypeError` с путём до
  поля ([narrowing.md](narrowing.md), раздел 3). Руками тоже можно — проверками и сужением.

## 6. Объявления для редактора

Чтобы tsc и VS Code понимали код на tz, компилятор будет поставлять файл объявлений своих
встроенных имён: `int`, `long`, `double`, `Result`, `ok`, `err`, `safeTry`, `Json`,
`embedJson`, `embedText` и др. Тогда писать в каждом файле `type int = number` не нужно.
Формат и способ подключения — вместе с инструментами для редактора.

`tests/errors`, обновление README.

   модуля, уникальные имена в exe, порядок загрузки модулей, выброс неиспользуемых экспортов,
   реэкспорт и `export *` с проверкой конфликтов, `as` в фигурных скобках, ошибки с
   подсказками на остальные формы.
2. **Циклы** (сделано). Граф импортов и проверка чтения при загрузке через модули (расширить проверку,
   которая уже есть внутри одного файла), сообщение с цепочкой.
3. **Файлы данных** (сделано; `embedBytes` — с [bytes.md](bytes.md), шаг 2). `embedJson` / `embedText`, тип `Json` с `null`, печать `Json` как в node.
   `JSON.parse` и `JSON.stringify` — после исключений ([errors.md](errors.md), шаг 2): разбор
   бросает `SyntaxError`.
4. **Объявления для редактора** — вместе с инструментами.
