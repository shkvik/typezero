# Ошибки: исключения и Result

Решения, принятые 23 октября 2026 года. Шаги 1–3 плана сделаны 24 октября; что осталось — в
конце, в разделе «План реализации». Классы, на которых держатся `Error` и его наследники,
описаны в [objects.md](objects.md).

## Коротко

- Бросать можно только `Error` и его наследников. В `catch (e)` у `e` всегда тип `Error`.
- Паник нет: всё, что раньше было паникой (деление `int` на ноль, `x!` на `undefined`,
  переполнение стека и т.д.), — исключение, которое можно поймать. Программу без возможности
  перехвата останавливают только сбои самого рантайма: кончилась память и т.п.
- `try` / `catch` / `finally` работают как в JS, включая `return` внутри `finally`.
- Исключение компилируется без таблиц раскрутки: ошибка лежит в ячейке рантайма, после вызова
  функции, которая может бросить, — одна проверка; функции, которые бросить не могут, ничего не
  платят; бросок стоит как `return`.
- `e.stack` — как в node.
- `Result` из neverthrow встроен: доступен без импорта, хранится без выделения памяти, цепочки
  методов компилируются в `if` / `else`, забытый `Result` — ошибка компиляции, `safeTry`
  работает без генераторов.

## 1. Исключения

```ts
class ParseError extends Error {
  constructor(public line: int, message: string) { super(message) }
}

throw new Error("нет файла")            // ок
throw new ParseError(3, "ждали цифру")  // ок
throw "нет файла"                       // ошибка, подсказка: throw new Error("нет файла")
```

- **Бросать можно только `Error` и его наследников**, поэтому у пойманного значения всегда
  есть `message` и `stack`.
- **`catch (e)`** — `e` всегда типа `Error`; вид уточняется через `instanceof`. Компилятор не
  вычисляет, что именно может вылететь из `try` (в tsc в strict-режиме `e` — `unknown`).
  `catch { ... }` без переменной тоже можно.
- **`finally`** работает как в JS. `return` внутри `finally` разрешён и, как в JS, отменяет
  летящее исключение: функция вернёт значение из `finally`, а исключение пропадёт.
- **Не пойманное исключение** — как в node: печатаются сообщение и стек, код выхода 1.
- **`e.stack`** — как в node: имена функций, файл и строка. Стек собирается по пути исключения
  наверх (каждая функция, через которую оно проходит, дописывает себя), поэтому стоит что-то
  только при броске. В exe для этого нужна небольшая таблица имён функций и номеров строк.

## 2. Паник нет

Всё, что раньше было паникой, — исключение, его можно поймать. Имена и тексты — как в JS, где
у JS есть такая же ошибка:

| Что | Исключение |
|---|---|
| `a / b`, `a % b` для `int` при `b = 0`; `0 ** -1` | `RangeError: Division by zero` (так JS отвечает на `1n / 0n`) |
| `x!` при `x == undefined` | `TypeError: x is undefined` |
| `reduce` пустого массива без начального значения | `TypeError: Reduce of empty array with no initial value` |
| `Math.round` и др. там, где ждут `int`, а число не помещается | `RangeError: 3000000000 does not fit in int` |
| `new Array(-1)`, `a.length = -1` | `RangeError: Invalid array length` |
| `"ab".repeat(-1)` | `RangeError: Invalid count value: -1` |
| переполнение стека | `RangeError: Maximum call stack size exceeded` |

**Переполнение стека.** Функция, которая может уйти в рекурсию (компилятор видит граф вызовов),
при входе сравнивает указатель стека с границей и, если места нет, бросает `RangeError` как
обычное исключение. Остальные функции ничего не платят; хвостовая рекурсия у нас и так цикл.
Это заменяет нынешний обработчик переполнения в Windows.

**Сбои самого рантайма** — кончилась память, ОС отказала в том, без чего рантайм не работает, —
поймать нельзя: сообщение и код выхода 2.

**Цена.** Функция, где есть такая операция, становится «может бросить», и после её вызова
появляется одна проверка. Компилятор её убирает, когда бросить нельзя: делитель — константа не
0 или уже проверен (`if (b != 0) return a / b`), `x!` после проверки и т.п.

## 3. Как исключения компилируются

Как обычный выход из функции (так в Swift, Go, Rust, Zig), а не через таблицы раскрутки стека,
как в C++:
- компилятор по всей программе знает, какие функции могут бросить; брошенная ошибка лежит в
  ячейке рантайма, функция выходит, как при `return`, и после её вызова — одна загрузка и
  проверка (предсказуемый переход). Сначала замерили второе возвращаемое значение `{T, ошибка}`:
  fib стал медленнее на 35–40%, потому что LLVM перестаёт превращать рекурсию в цикл; с ячейкой
  fib не меняется. С потоками ячейка станет своей у каждого потока;
- функции, которые бросить не могут (большинство), ничего не платят;
- бросок стоит как обычный `return`; освобождение локальных переменных идёт тем же путём, что
  при `return`;
- таблицы раскрутки и раскрутчик не нужны — exe меньше.

## 4. Result (neverthrow)

[neverthrow](https://github.com/supermacro/neverthrow) встроен в язык: ошибка возвращается как
значение `Result<T, E>` — `Ok` со значением или `Err` с ошибкой.

```ts
type ParseError = "пусто" | "не число"

function parseIntSafe(s: string): Result<int, ParseError> {
  if (s.length == 0) return err("пусто")
  const n = parseInt(s)
  return isNaN(n) ? err("не число") : ok(n)
}

const text = parseIntSafe("42")
  .map(n => n * 2)
  .match(n => "получилось " + n, e => "ошибка: " + e)
```

- **Без импорта.** `Result`, `Ok`, `Err`, `ok`, `err`, `safeTry` и остальное — встроенные имена.
  Строка `import { ... } from "neverthrow"` из существующего кода разрешена и указывает на
  них же, поэтому такой код компилируется без правок. Свои переменные с теми же именами
  (`catch (err)`, `const ok = ...`) перекрывают встроенные, как обычно.
- **Значение, а не объект в куче.** `Result` хранится как метка Ok/Err и значение, без выделения
  памяти. Цепочка `.map(...).andThen(...).match(...)` компилируется в обычные `if` / `else`,
  лямбды встраиваются (в JS каждый `ok(...)` — объект, а каждый `.map` — ещё и замыкание).
  Печать как в node: `Ok { value: 84 }`, `Err { error: 'пусто' }`.
- **`==` на `Result`** — ошибка компиляции: в JS `ok(1) == ok(1)` — `false` (два объекта),
  а значения сравнивать нечем. Сравнивать — через `match`, `isOk()`, `value`.
- **Забытый `Result` — ошибка компиляции.** `saveFile("")` без использования результата значит,
  что ошибку никто не проверит (в JS для этого ставят правило линтера must-use-result). Если
  результат правда не нужен — присвоить переменной или обработать `.match`.
- **`safeTry`** — ранний выход при ошибке:
  ```ts
  function sum(a: string, b: string): Result<int, ParseError> {
    return safeTry(function* () {
      const x = yield* parseIntSafe(a) // Err → sum сразу возвращает его; Ok → x = число
      const y = yield* parseIntSafe(b)
      return ok(x + y)
    })
  }
  ```
  `const x = yield* r` внутри `safeTry` значит «если `r` — Err, вернуть его, иначе взять
  значение». Компилятор переводит это в обычные `if` и `return`, без генераторов.
- **API сразу:** `ok`, `err`, `Result`, `Ok`, `Err`; `isOk`, `isErr`, `value`, `error`, `map`,
  `mapErr`, `andThen`, `orElse`, `match`, `unwrapOr`, `andTee`, `orTee`, `andThrough`;
  `Result.combine`, `Result.combineWithAllErrors`, `Result.fromThrowable`, `safeTry`;
  `_unsafeUnwrap` / `_unsafeUnwrapErr` (бросают `Error`).
- **Вместе с async:** `ResultAsync`, `okAsync`, `errAsync`, `fromPromise`, `fromSafePromise`,
  `asyncMap`, `asyncAndThen`.

`Result.fromThrowable` связывает два способа: функцию, которая бросает, превращает в функцию,
которая возвращает `Result`.

## План реализации

На каждом шаге: тесты `tests/run` (с `// same-as-node`, где поведение совпадает с JS), ошибки в
`tests/errors`, прогон с `-O0` и `-O2` под `TZ_CHECK_LEAKS=1`, обновление README.

1. **Result** (сделано). Встроенный тип `Result<T, E>` (как `Array<T>`: компилятор знает его сам, общие
   generics не нужны), `ok` / `err` с выводом недостающей половины типа из контекста и из
   других `return`, сужение после `isOk()` / `isErr()`, методы с лямбдами (как методы массивов
   с колбэками), печать, ошибка на `==` и на забытый `Result`, `safeTry`, `combine`. От
   объектов не зависит.
2. **Исключения** (сделано). `throw` / `try` / `catch` / `finally`, `Error` и встроенные наследники
   (`TypeError`, `RangeError`, `SyntaxError`), свои наследники `Error` (нужны классы — шаги 3–4
   плана объектов); ячейка ошибки и вывод «может бросить» по всей программе;
   освобождение переменных на пути ошибки; `e.stack`; не пойманное исключение;
   `Result.fromThrowable`, `_unsafeUnwrap`.
3. **Паники → исключения** (сделано). Все бывшие паники из таблицы; проверка стека при входе в
   функции, которые могут уйти в рекурсию, вместо обработчика переполнения в Windows.
4. **ResultAsync** (сделано) — вместе с async.
