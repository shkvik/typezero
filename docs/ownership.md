# Владение: кто владеет значением и кто на него смотрит

Решения приняты 25–26 ноября 2026 года (наброски — `tmp/design/*.tz`, план —
`tmp/design/plan.md`). Модель — как в Rust: у значения один владелец, остальные берут его на
время. Времён жизни в записи нет: заимствование живёт до последнего использования и не уходит
из функции, кроме результата `Read<T>` / `Mut<T>`.

Проверка обязательна: `tzparse build` не собирает программу с ошибкой `TZ40xx`; отдельно её
печатает `tzparse types main.tz --ownership`. С 27 ноября 2026 года у значения с одним
владельцем счётчика нет: его не увеличивают, а освобождают, когда уходит владелец (раздел 7).
Счётчик остался только у копируемых значений. `Cell` и `Interned` убраны из языка 27 ноября
2026 года (раздел 6).
Компилятор self проходит проверку без ошибок. Что ещё не сделано — в конце, в разделе «Что не сделано».

## Коротко

- **Параметр без обёртки меняют** (`Mut`). `Read<T>` — только читать, `Own<T>` — забрать себе,
  `Lent<T>` — читать, и результат может смотреть в этот параметр, `Once<F>` — колбэк, который
  позовут один раз. Режим пишут в заголовке, а не выводят из тела: правка тела не ломает
  вызовы. Компилятор подсказывает «можно `Read`» и «можно `readonly`», это не ошибки.
- **`readonly` перед методом** — метод только читает `this`. Методов, которые забирают `this`,
  нет: содержимое забирают `take(this.items)` в обычном методе. У метода интерфейса тоже
  пишут `readonly`; без пометки он меняет `this`. Компилятор верит пометке и проверяет её там,
  где метод написан: класс реализует `readonly`-метод интерфейса тоже `readonly`,
  переопределение `readonly`-метода — тоже `readonly`.
- **Копируется** тип, у которого все поля `readonly` и копируемые (унаследованные тоже), и у
  класса нет наследников. Остальные значения переезжают: после `const b = a` имя `a` пусто.
  Копия или переезд — решает тип места, куда кладут: копируемое значение, положенное туда, где
  тип не копируется, забирается; нужна копия — `structuredClone`.
- **Заимствование** — `const p = list[0]`, элемент `for…of`, результат `find` / `at` /
  `Map.get`. Пока оно живо, источник нельзя менять. Читать или менять через заимствование —
  решает его использование в функции.
- **Результат-заимствование** пишут `Read<T>` / `Mut<T>`; он смотрит в `Lent`-параметры, а без
  них — в `this`. Положить заимствование в поле нельзя.
- **Поле забирают** только `replace`, `take` и `swap` из `tz:mem`: поле ни на миг не пустое.
- **Замороженный заём**: что взято от `this` только через `readonly`-поля и попало в глубоко
  неизменяемое значение или в элемент `readonly`-массива, не мешает `Mut`-методам `this`
  (раздел 3).
- **Общие графы** (AST, типы) живут в хранилище у одного хозяина, наружу ходят копируемые
  записи с номерами (`id`), как в rustc; `Cell` и `Interned` нет (раздел 6).
- Глобального `let` нет. **Статическое поле** заполняют из любой функции, но заменить его
  целиком можно только там, где оно объявлено, или на верхнем уровне модуля; пока кто-то
  смотрит внутрь поля, его не меняют ни в той же функции, ни вызовом функции, которая его
  меняет (раздел 6).

## 1. Параметры и `this`

```ts
function length(point: Read<Point>): double {
  return Math.sqrt(point.x * point.x + point.y * point.y); // tz: ок — только читает
}

function shift(point: Point): void {
  point.x += 1; // tz: ок — Mut по умолчанию
}

class List {
  private readonly items: Point[];

  public add(point: Own<Point>): void {
    this.items.push(point); // tz: ок — точка теперь у списка
  }

  public readonly size(): int {
    return this.items.length; // tz: ок — readonly: this только читают
  }
}
```

Ошибки:

| Код    | Когда                                                                     |
|--------|---------------------------------------------------------------------------|
| TZ4010 | параметр без `Own` кладут в поле или массив                               |
| TZ4021 | меняют то, что взято только для чтения (`Read`-параметр, `readonly`-метод) |
| TZ4031 | `Lent` у копируемого типа: значение и так копируется                     |
| TZ4052 | переопределение `readonly`-метода без `readonly`                          |
| TZ4053 | метод интерфейса `readonly`, а в классе, который его реализует, — нет      |

`Mut` у копируемого типа (`Mut<int>`) — ошибка TZ4037: менять копию бессмысленно, вернуть
значение можно результатом.

Подставить `Circle[]` туда, где ждут `Shape[]`, решает режим: через `Read` и `Own` — можно,
через `Mut` — нельзя (TZ4038): функция могла бы положить туда квадрат. То же у объекта с
изменяемым полем. Типы функций совпадают точно.

## 2. Переезд и копии

```ts
const mark = new Mark(1, 1); // поле column не readonly — Mark не копируется
const other = mark;

console.log(mark.line); // tz: ошибка TZ4004 — mark отдан строкой выше
```

- Значение отдают: присваиванием в новое имя, в поле, в массив, в `Own`-параметр, `return`.
- В цикле отдать можно только то, что объявлено в теле: иначе на втором проходе пусто
  (TZ4005).
- Spread объекта забирает некопируемые поля, которых литерал не переписал; spread массива
  копируемых элементов — копия.
- Деструктуризация `const { name, center } = shape` даёт копию `name` и заимствование `center`.
- Тип переменной решает, копия это или переезд: `const narrowed: Shape = new Circle(1)` — у
  `Shape` есть наследник, он не копируется, и `const copied = narrowed` отдаёт значение, хотя
  проверка знает, что там `Circle`. Сужение до числа, строки или `boolean` — копия при любом
  типе переменной.
- Копируемое значение, положенное туда, где тип не копируется (`const shape: Shape = circle`,
  поле, элемент `Shape[]`, `Own`-параметр, `return`), забирается: дальше `circle` нельзя
  (TZ4004). Нужна копия — `structuredClone(circle)`, она делает новый объект. Из поля,
  `Read`-параметра или элемента массива забрать нельзя (TZ4008 / TZ4010 / TZ4025); переменная
  `const shape: Shape = this.circle` только смотрит на поле.
- Контейнер копируемых не становится контейнером некопируемых: `const shapes: Shape[] =
  circles` при `circles: Circle[]` — ошибка TZ4048 (так же `Map`, `Set`, кортежи, записи и
  spread `[...circles]`). Копии `Circle` могут делить один объект, а в `Shape[]` у каждого
  элемента один хозяин. Собирают `Shape[]` сразу или копируют элементы через `structuredClone`.
- Наследник класса с изменяемыми полями не копируется, даже если своих полей у него нет
  (`class Tag extends Named {}` при `name: string` в `Named`).
- Изменяемое значение нельзя передать как копируемый тип (TZ4047): если `part` выведен
  `{ module: int; item: int }`, а параметр — копируемый `PartTarget` (поля `readonly`), то
  вызов разделил бы одно значение на двоих. Пишут тип там, где значение сделано:
  `const part: PartTarget = { module, item }`.
- `concat` массива некопируемых элементов забирает и получатель, и аргументы (как
  `let mut all = a; all.extend(b)` в Rust): `const more = items.concat(extra)` — дальше `items`
  нельзя (TZ4004); получатель-поле или `Read`-параметр — ошибка.
- `new Map(m)`, `new Set(items)`, `new Map(pairs)` — как spread: копируемые элементы
  копируются, источник жив, как в JS; некопируемые из своего источника переезжают, и источник
  отдан (`new Map(first)` — дальше `first` нельзя, TZ4004); из заимствованного (поле,
  `Read`-параметр) — ошибка TZ4008 / TZ4010 с подсказкой `structuredClone` / `take` /
  `Own<T>`. Глубокая копия пишется явно: `new Map(structuredClone(first))`.
- Копируемые классы сравнивают `==` только с `[Symbol.equals](other)` — у копии нет адреса
  (TZ4034); ключ `Map` / `Set` такого типа требует ещё `[Symbol.hash](hasher)` (TZ4035);
  `WeakRef` на копируемое — ошибка (TZ4036).

## 3. Заимствования

```ts
const points = [new Point(1, 1)];
const first = points[0]; // заимствование

points.push(new Point(2, 2)); // tz: ошибка TZ4006 — first ещё смотрит в points
console.log(first?.x);
```

- Заимствование живёт до последнего использования. То, что используют в правой части
  присваивания, сделано до записи: `this.state = merged(this.state)` — можно.
- `for…of` держит массив: менять его в цикле — ошибка (TZ4022). Цикл по индексу — можно.
- `filter` и `slice` у некопируемых элементов дают массив заимствований; `view(start, end)` —
  вид без копии; `drain()` забирает все элементы, `retain(fn)` убирает лишние на месте.
- `for (using x of items)` — только по `items.drain()`: освободить можно только своё (TZ4032).
- Локальный массив `const views: Read<Point>[] = []` может собирать заимствования, и пока он
  жив, источник занят.
- Поле не держит заимствований (TZ4030), даже внутри: `Generator<Read<T>>` в поле — ошибка.
- Аргументы вычисляются слева направо, и `Own`-аргумент уходит сразу: `f(x, x.name)` с
  `Own`-первым — ошибка TZ4004 (второй аргумент читал бы уже отданное).

### Замороженный заём (правило readonly-цепочки)

```ts
class Walker {
  private readonly store: Store; // readonly-поле, внутри readonly-массивы
  private count: int;

  public walk(): void {
    for (const item of this.store.items) {
      this.note(item.name); // tz: ок — item заморожен: через readonly его не изменить
    }

    const tree = this.store.tree; // глубоко неизменяемое дерево
    const first = tree.exprOf(0); // заём через readonly-метод — тоже заморожен

    this.note("x"); // tz: ок — Mut-метод this, пока tree и first живы
  }
}
```

- Заём заморожен, если до него дошли от `this` (или от замороженного имени) только через
  `readonly`-поля, элементы `readonly`-массивов и `readonly`-методы с копируемыми аргументами,
  и он попал в глубоко неизменяемое значение (все поля `readonly`, вглубь — то же) или лежит
  под `readonly`-массивом (через `readonly T[]` элемент только читают). Такой заём не мешает
  `Mut`-методам `this`: TZ4006, TZ4011 и TZ4022 его не видят. Переписать или забрать само
  поле, на котором он держится, по-прежнему нельзя.
- Под `readonly`-массивом заём заморожен, даже если элемент не глубоко неизменяемый (например,
  в нём `Buffer`) — временное правило, решение ждёт (Н13 в tmp/selfhost/findings.md).

## 4. Результат-заимствование и `Lent`

```ts
class Polygon {
  private readonly points: Point[];

  public readonly first(): Read<Point> | undefined {
    return this.points[0]; // tz: ок — результат смотрит в this
  }

  public readonly nearer(a: Lent<Point>, b: Lent<Point>): Read<Point> {
    return a.x < b.x ? a : b; // tz: ок — результат смотрит в a или b
  }
}
```

- Без обёртки результат свой: новый, вынутый или отданный. Вернуть заимствование как своё —
  ошибка TZ4012.
- `Read<T>` / `Mut<T>` смотрит в `Lent`-параметры, а если их нет — в `this`. Функция без `Lent`
  и без `this` заимствование вернуть не может (TZ4014).

## 5. `tz:mem`: забрать с заменой

```ts
import { drop, replace, swap, take } from "tz:mem";

const old = replace(this.weapon, next); // кладёт next, отдаёт прежнее
const items = take(this.items); // оставляет [], отдаёт прежний массив
swap(this.weapon, this.backup);
drop(a); // освободить сейчас; дальше a пусто
```

- `take` оставляет пустое значение типа: `undefined`, `[]`, `""`, `0`, `false`; у типа без
  пустого значения — ошибка TZ4029, нужен `replace`.
- Первый аргумент — место: имя, поле, элемент. Новое значение местом не бывает (TZ4033).
- `structuredClone(value)` — глубокая копия, своя. Функцию, итератор и ресурс (класс с
  `[Symbol.dispose]`) она не копирует: TZ4044 называет поле (`log: File`) и просит класс с
  `[Symbol.clone]()`, который знает, как себя копировать.
- Значение с лишними полями кладут в копируемый тип-запись (`const span: Span = item`, где у
  `item` есть ещё `label`): если источник копируемый — это копия полей; если его можно менять —
  `span` заимствует его для чтения: пока `span` нужен, источник не меняют (TZ4006), а в поле
  `span` не положить — копию пишут литералом.
- Список по ключу `Map` пополняют так: `get` и, если ключа нет, `set` нового —
  `const list = groups.get(word); if (list == undefined) groups.set(word, [line]); else
  list.push(line)`. Старый приём `const list = groups.get(word) ?? []; list.push(line);
  groups.set(word, list)` по правилам не проходит: `list` то смотрит в `groups`, то свой.

## 6. Общее состояние без `Cell` и `Interned`

`Cell` (поле, которое меняют и через `readonly`) и `Interned` (бессмертное общее значение)
убраны из языка 27 ноября 2026 года: `Cell` обходил `readonly`, а `Interned` делал всё
помеченное бессмертным. Вместо них три приёма, как в rustc:

- **Хранилище с номерами.** Общий неизменяемый граф (AST, типы) живёт в таблицах у одного
  хозяина; записи плоские и копируемые, дети — номера (`lhsId`, `itemId`), списки — диапазоны
  в таблице. Пример — `AstTree` в self: `tree.exprOf(id)`, `tree.stmtsOf(block.bodyList)`.
  Сравнивают и кладут в `Map` / `Set` номер (`a.id == b.id`), а не саму запись: у копии нет
  адреса (TZ4034 видит и объединения записей, и `includes` / `indexOf` по ним).
- **Один хозяин у службы.** Изменяемая служба (`TypeStore`, журнал ошибок, кэши) — поле одного
  хозяина; остальные смотрят через него (`this.values.types.store`).
- **Помощник — параметром или частью хозяина.** Кому служба нужна на время, получает её
  параметром `Read<T>` / `Mut<T>` на вызов; помощник без своего состояния — часть
  (`partial`) класса-хозяина.

Литералы и константы модулей по-прежнему бессмертны: их не освобождают.

### Статические поля

Статическое поле владеет своим значением, как переменная, только видно оно из любой функции
без передачи. Поэтому правила такие (решено 27.11, пример — tmp/design/statics.tz):

- Заполнять можно отовсюду: `Store.cache.set(...)`, `push`, `delete`, `clear`, изменения
  внутри. Поставить на место поля другое значение (`Store.cache = new Map()`) функция не может
  (TZ4049) — только объявление поля или верхний уровень модуля. Копируемое поле
  (`static count: int`) меняют целиком: внутрь копии никто не смотрит.
- Пока заимствование смотрит внутрь поля (`const first = Store.cache.get("a")`, элемент
  `for…of`), поле не меняют: в той же функции — TZ4006 / TZ4022, как у переменной; вызовом —
  TZ4054. Какие поля меняет функция, компилятор узнаёт сам: по её телу, телам функций, которые
  она зовёт, и колбэкам, которые ей передают. Вызов значения-функции, метода интерфейса или
  поля-функции считается «может менять всё».
- Значение поля не отдают (TZ4050) и не одалживают наружу результатом `Read<T>` (TZ4051):
  вызывающий не видит, что результат смотрит в поле. Нужна копия — `structuredClone`, или
  вызывающий читает поле сам.
- Статический метод проверяется как обычная функция: его `Own`-параметры забирают аргумент.
- В сборке значение поля живёт в глобальной переменной; инициализатор выполняется там, где
  объявлен класс, а в конце программы значение освобождается. Статический метод зовут без
  объекта. Поле без типа с литералом получает тип литерала (`static count = 0` — `int`),
  `static readonly` с целым литералом — ещё и константа для проверок диапазона.

## 7. Память

- Параметр без `Own` / `Once` заимствован: вызывающая не трогает счётчик, вызываемая не
  освобождает. Если тело присваивает такому параметру, освобождается только то, что присвоило
  тело (флаг места, как drop flag в Rust).
- Перенос своей переменной — `return x`, `const b = a`, запись в поле или элемент, передача в
  `Own`-параметр — забирает значение без счёта: место пустеет. Где перенос, решает проверка
  владения: она же запрещает трогать переменную после него. Так же уходит поле своего значения
  (`return { file: result.file }`): на его место ложится пустое. `replace` и `take` отдают
  старое значение без счёта.
- Заимствование не трогает счётчик: переменная, которая только смотрит (`const p = list[0]`,
  `const x = obj.field`, элемент `for…of`, результат `find`, `Map.get`, `Read<T>`-метода),
  параметр колбэка, массив, по которому идёт `for…of`. Если в такую переменную попало новое
  значение, флаг места велит освободить его в конце блока.
- Результат `Read<T>` / `Mut<T>` функция отдаёт без счёта. Если он смотрит во временный объект
  (`make().first()`), вызывающий берёт счёт, пока объект не освободился.
- `a ?? b` с заимствованным `a` тоже без счёта: значение несёт флаг «своё ли оно» (как drop
  flag в Rust) — в переменной, в источнике `for…of` и в аргументе заимствованного параметра
  освобождается только `b`, если взято оно. Своё `a` переезжает в результат.
- Конструктор не отдаёт поле `this` (TZ4008, как и любой метод): после конструктора методы
  читают поле, оно не должно быть пустым. Отдать можно параметр, пока он не лёг в поле.
- Освобождение объекта класса сначала вызывает его `[Symbol.dispose]()`, затем `dispose`
  базы — сам; вызывать `super[Symbol.dispose]()` в наследнике — ошибка TZ3540 (база
  освободилась бы дважды).
- **Один владелец — без счётчика.** У значения некопируемого типа (массив, объект, экземпляр
  класса, функция-значение, `Map`; без копируемых вариантов в объединении) счётчик не
  увеличивают: второго держателя у него нет. Когда владелец уходит, значение освобождают
  сразу. Счётчик в заголовке объекта остаётся и равен 1; бессмертные значения (литералы,
  константы модулей) не освобождают. Копируемые значения (строки, копируемые записи и классы)
  по-прежнему делятся счётчиком — их не меняют, делить их можно.
- Когда копируемый объект становится значением некопируемого типа (`Circle` → `Shape`), lower
  проверяет счётчик: 1 — объект берут как есть, больше — кладут его копию, а свой счёт отдают
  (как `Rc::unwrap_or_clone` в Rust). Так у `Shape` всегда один хозяин, даже если раньше
  сделали `const other = circle`. `structuredClone` копируемого объекта делает новый объект,
  а не прибавляет счёт старому.
- **Массив заимствований** `Read<T>[]` смотрит на элементы, а не владеет ими: при `push` их не
  считают, при освобождении освобождают только сам массив. Такой массив дают `slice`,
  `filter`, `view` и `Array.from` над некопируемыми элементами (`items.slice(1)` — заём у
  `items`, его нельзя вернуть как своё или положить в поле), `Map.keys()` / `values()` в
  библиотеке на tz и функции с результатом `Read<T>[]`. Кортеж заимствований
  `[Read<K>, Read<V>]` (элементы обхода `Map`) так же не освобождает некопируемые части.
- `--check-counts` у `tzparse build` — тестовый режим: перед каждым освобождением значения с
  одним владельцем программа проверяет, что счётчик равен 1, иначе паникует с типом и местом
  («an own value is freed while something else still counts it»); в этом режиме счётчик
  снова ведут, чтобы поймать второго держателя. `--audit-counts` печатает места, где lower
  при сборке добавил бы счёт значению с одним владельцем; в self таких мест 0.

### Функция как значение

Стрелка и функция-выражение, которые не встроены в вызов (`map`, `filter` и т.п. компилятор
встраивает), — объект: код лежит в описании объекта, захваченное — в его полях. Замыкание,
которое живёт только во время вызова (колбэк `Read`-параметра, локальная стрелка), захватывает
всё адресом — и `let`, и константы, и `this`: ничего не считает и не освобождает (как `&` в
Rust). Сохраняемое замыкание (`Own` / `Once`) забирает захваченное значение с одним
владельцем себе: место снаружи пустеет, проверка запрещает его трогать дальше; копируемое
захватывает копией. `let` сохраняемому колбэку брать нельзя (TZ4016).
Сохраняемый ли колбэк, проверка узнаёт по параметру: `Own<…>` / `Once<…>` — у функции, у
метода класса и у метода `interface`.
Функция, объявленная по имени, как значение — один объект на программу, его не освобождают.

## 8. `tz:unsafe` и runtime на tz

Код, которому нужна сырая память, пишут на tz поверх `tz:unsafe`; импортировать этот модуль
можно только из library — программа получает безопасные обёртки. Опасную функцию можно звать только
внутри функции или метода с пометкой `@Unsafe({ uses: [UnsafeUse.Memory], reason: "почему здесь всё
верно" })` (TZ4039); `reason` обязателен и не пуст (TZ4040); `uses` перечисляет ровно то,
что тело делает (TZ4041 — не хватает, TZ4042 — лишнее). Если у `@Unsafe` есть `requires`
(условие для вызывающего, как `unsafe fn` в Rust), саму функцию тоже можно звать только из
`@Unsafe` (TZ4043); без `requires` она — безопасная обёртка, звать её может любой.

```ts
import { Raw, allocate, putAt, takeAt } from "tz:unsafe";

export class List<T> {
  private data: Raw<T>; // адрес ячеек; длины и владения не несёт, копируется как число
  private count: int;
  private capacity: int;

  public push(item: Own<T>): void {
    // ...рост через reallocate...
    putAt(this.data, this.count, item); // ячейка count была пустой — теперь полна
    this.count += 1;
  }
}
```

- `Raw<T>` — адрес подряд идущих ячеек под `T`. `allocate` / `reallocate` / `release` — память;
  `putAt` кладёт в пустую ячейку, `takeAt` забирает из полной, `peekAt` даёт посмотреть
  (заимствование без источника, как `&*ptr` в Rust: его можно вернуть как `Read<T>`, нельзя
  положить в поле или свой массив),
  `destroyAt` освобождает значение в ячейке так, как освобождается `T`, `shiftCells` двигает
  ячейки, `forget` забывает значение без освобождения. Размер ячейки — размер `T` в памяти.
- Обобщённые функции, классы и методы компилятор переводит копией на каждый набор типов, как Rust:
  `List<int>` и `List<string>` — разный код.
- Уже на tz: `List<T>` (`tz:list`); встроенные `Map` и `Set` — это `HashMap<K, V>` из `tz:map`
  (порядок обхода — порядок вставки, как в JS; хеш ключа — `hashOf`, который компилятор строит
  под тип ключа; печать `console.log` — как у node); у массива — `indexOf`, `lastIndexOf`,
  `includes`, `reverse`, `slice`, `concat` (library/core/array.tz; для чисел с плавающей точкой
  и необязательных элементов пока C). Остальной runtime — на C.
- Код library на tz (`tz:map`, `tz:list`, `tz:array`) проходит ту же проверку владения, что и
  программа. Массив заимствований пишется `Read<T>[]` (и кортеж — `[Read<K>, Read<V>]`):
  `push` кладёт в него заимствования, `return` отдаёт его как результат-заимствование, если
  всё, на что он смотрит, — из `Lent`-параметров.
- Элементы массива освобождает код, который компилятор строит под тип элемента: строки,
  объекты, вложенные массивы — каждый своим способом. C освобождает только память самого
  массива.

## 9. Что не сделано

- Механизм памяти: у значения с одним владельцем счётчика нет, но заголовок со счётчиком у
  объекта остался (его читают C-функции runtime и проверка `--check-counts`). Где C runtime
  копирует массив некопируемых элементов, он ещё прибавляет счёт (`tz_arr_slice`,
  `tz_arr_append` у копируемых, натив `Map` не из `tz:map`); освобождение тогда не
  срабатывает — утечка, не порча памяти. `Array.from(map.entries())` lower пока не переводит.
  Обобщённые классы с базой, `instanceof` и абстрактные методы lower пока не переводит.
- У `@Unsafe` не разбираются пометки класса (`send` / `share`) — они нужны задачам.
- `Map` / `Set` внутри объекта или массива `console.log` печатает внутренностями `HashMap`;
  длинную карту node печатает в несколько строк, tz — в одну. С tz-картами self проверяет
  себя медленнее, чем с C-картами (около 15 %).
- `Shared` / `SharedMut` / `Mutex` со стражами (в library их нет), задачи.
- `structuredClone` некопируемых объектов и классов не собирается: только копируемые значения
  (числа, строки, копируемые записи и классы) и массивы копируемых элементов.
- Параметры библиотеки без пометки (`*.d.tz`) считаются `Read` — что принять для объявлений,
  ждёт решения (Н7 в tmp/selfhost/findings.md). Методы интерфейсов из объявлений library
  без пометки считаются читающими по той же причине.
- Обход статического поля методом с колбэком, который меняет это же поле (`Store.items.forEach(() => Store.items.pop())`), проверка не
  ловит: получатель вызова — не заимствование в переменной.
