# Рекурсия → цикл: приёмы

Каталог приёмов, которыми рекурсию в компиляторе заменяем циклом. Каждый приём: по какому
признаку узнать, как было, как стало, на что смотреть. Пополняется по мере работы; короткие
правила — в `code_style.md`, раздел «Обходы без рекурсии»; ход работы — `tmp/recursion_plan.md`.

Перед любым переводом сверить пять вещей — поведение не должно поменяться:

1. **порядок** обхода (кто «первый найденный», в каком порядке пишутся сообщения);
2. **ранний выход** (где рекурсия бросала работу);
3. **побочные действия** узла (ошибки, создание узлов, достраивание классов);
4. **повторы** («уже был» — у всех типов или только у объектов);
5. **сведения сверху вниз** (метки, глубина, знак под `!`, «внутри функции»).

---

## 1. Поиск по телу — список с местом и `for`

**Признак:** вопрос «есть ли где-то в теле X», ответ узла от детей не зависит.

**Было** — рекурсия со счётчиками вокруг спуска (`++loops; in(body); --loops;`).

**Стало** — тело раскладывается один раз в списки с местом (`PlacedNodes`, обход в ширину,
очередь — сами списки), вопрос — `for` с ранним `return`:

```cpp
bool Exits::in(llvm::ArrayRef<const Stmt *> stmts) const {
  PlacedNodes nodes = PlacedNodes::collect(stmts, {});
  for (const PlacedStmt &placed : nodes.getStmts()) {
    if (placed.place.isInsideFunction()) {
      continue;
    }
    auto *exit = dyn_cast<BreakStmt>(placed.stmt);
    if (exit != nullptr && this->breakLeaves(exit, placed.place)) {
      return true;
    }
  }

  return false;
}
```

**Смотреть:** старые обходы обычно не заходили во вложенные функции — первым в цикле пропуск
`isInsideFunction()`. Раскладывается всё тело, раннего выхода в раскладке нет.

**Где:** `Exits::in`, `ReturnChecker::breaksTo`, `LoopChecker::continuesTo`,
`ReturnInferrer::returnsValue`, `Destination::findReturnValues`, `FlowChecker::staysLocal`,
`LoopScanner`.

## 2. Обход через `AstWalker` с колбэком — тот же список и `for`

**Признак:** `AstWalker::visitExprs(body, [&](const Expr *e) { ... })`.

**Стало:** `PlacedNodes::collect` и `for`; там, где был `intoFunctions = false`, — пропуск
`isInsideFunction()`.

**Смотреть:** не переводить, если колбэку важен порядок (сообщения со списком имён, сбор в
вектор, порядок объединения типов) — у `PlacedNodes` обход в ширину. `AstWalker` с
`intoFunctions = false` не видит инициализаторы полей экземпляра, а `PlacedNodes` видит.
`AstWalker::collectNames` — свои правила (имя у `new`, без декораторов) — не 1:1.

**Где:** `AssignedFields`, `MetadataWriters`, `LateClasses::hasClassExpr`, `CallCycles::memberCallsIn`,
`ArgListChecker::usedAsValue`, `PromiseChecker::callsWithValue`, `RegexChecker::assignsName`.

## 3. Цепочка — `while`

**Признак:** спуск всегда в одного ребёнка: `member->object`, `conv->operand`, `type->inner()`,
`call->args[0]`, `cls->parent`.

**Стало:** идём по цепочке, складываем то, что нужно, потом собираем с начала:

```cpp
std::optional<std::string> ObjectChecker::chainText(const Expr *expr) {
  std::vector<llvm::StringRef> names;
  const Expr *link = ObjectCheckHelpers::unnarrowed(expr);
  while (auto *member = dyn_cast<MemberExpr>(link)) {
    if (member->optional) {
      return std::nullopt;
    }
    names.push_back(member->name);
    link = ObjectCheckHelpers::unnarrowed(member->object);
  }
  auto *root = dyn_cast<NameExpr>(link);
  if (root == nullptr) {
    return std::nullopt;
  }
  std::string text = root->name.str();
  for (llvm::StringRef name : llvm::reverse(names)) {
    text += "." + name.str();
  }

  return text;
}
```

**Разновидности:**
- проверка на каждом уровне — собрать звенья, проверить у всех (`ConstantFolder::intConstant`:
  приведения собираются, значение проверяется на влезание в тип каждого);
- запасной ответ на каждом уровне — собрать звенья и пройти их с конца, у каждого «есть ответ
  ребёнка — использовать, нет — свой запасной» (`CryptoArgs::knownNumber`);
- снятие обёрток «того же размера» — `while` до первого узла, у которого обёртки нет
  (`IndexProofs::sameLengthSource`, `viewedSource`).

**Смотреть:** «не получилось» — `std::optional`, а не пустая строка.

## 4. Рекурсия на один уровень — вынести ветку

**Признак:** функция зовёт себя только для узла, который точно попадёт в другую ветку
(`x.length - k` → только `x.length`; `globalThis.crypto` → только `globalThis`).

**Стало:** эта ветка — отдельная функция, обе ветки зовут её (`LoopBounds::memberRange`,
`CallChecker::namesGlobal` + `isGlobalThisMember`).

## 5. Однородное дерево — разложить стеком в список, потом `for`

**Признак:** дерево из узлов одного вида (`&&`, `&&`/`||`, `?:`, арифметика, литералы
массива/объекта), вопрос «есть ли часть…» или «все ли части…».

**Стало:** `ExprParts` раскладывает слева направо (стек + `while`), вопрос — `for`:

```cpp
bool VarChecker::isTextChoice(const Expr *expr) {
  for (const Expr *branch : ExprParts::choiceBranches(expr)) {
    if (!isa<StringLitExpr>(branch)) {
      return false;
    }
  }

  return true;
}
```

`ExprParts`: `andParts`, `logicParts`, `choiceBranches` (снимает неявные приведения),
`operatorTree`, `literalLeaves`.

**Смотреть:** правила снятия приведений у функций разные — если своё правило
(`IndexProofs::provesBetween` снимает только расширяющие), своя раскладка рядом
(`provedBranches`). Вопрос, который проверяет и внутренние узлы, проверяет их в цикле:
`isLiteralNode` для каждого узла `operatorTree`.

## 6. Части типа — маршрут

**Признак:** «есть ли внутри типа X», «собрать из типа Y».

**Стало:** `TypeParts::collect(type, маршрут)` (стек, порядок как у рекурсии, «уже был» на весь
обход) и `for`. Маршрут — список `TypeEdge`, куда функция **идёт**; все маршруты рядом в
`type_routes.h`, расхождения между функциями видны глазами:

```cpp
inline constexpr TypeEdge kHoldsRoute[] = {
    TypeEdge::OPTIONAL, TypeEdge::ARRAY,  TypeEdge::PROMISE,      TypeEdge::DICT,
    TypeEdge::UNION,    TypeEdge::FIELDS, TypeEdge::CLASS_FIELDS,
};

bool LateClasses::holdsType(const Type *type, const Type *target) {
  TypeParts parts = TypeParts::collect(type, kHoldsRoute);

  return llvm::is_contained(parts.getTypes(), target);
}
```

**Смотреть:** особые правила — отдельный вид перехода, описанный один раз (`CLASS_FIELDS` — без
него класс конец пути; `TYPE_ARGS` — аргументы вместо полей). Отвергнуто: общий обход + список
пропусков в каждой функции (логика наизнанку). Запись типа (`TypeRef`) — `TypeRefParts`.

## 7. Ответ узла из ответов детей — стековая машина

**Признак:** ответ узла склеивается из ответов детей (текст выражения, линейная форма,
вычисление константы, новый тип из частей).

**Стало:** запись «детьми вперёд» (post-order: прямой обход стеком и разворот), потом проход
со стеком ответов — как калькулятор в обратной польской записи:

```
a.b[i]  ->  запись: a   a.b   i   a.b[i]
a       -> кладём "a"                   стек: "a"
a.b     -> снимаем 1, кладём "a.b"      стек: "a.b"
i       -> кладём "i"                   стек: "a.b" "i"
a.b[i]  -> снимаем 2, кладём "a.b[i]"   стек: "a.b[i]"
```

```cpp
std::optional<std::string> UnaryChecker::assertedText(const Expr *expr) {
  std::vector<std::string> answers;
  for (const Expr *node : ChildrenFirst::order(expr, UnaryChecker::textParts)) {
    std::optional<std::string> text = UnaryChecker::nodeText(node, answers);
    if (!text.has_value()) {
      return std::nullopt;
    }
    answers.push_back(*text);
  }

  return answers.back();
}
```

Дети узла даёт функция вопроса (`textParts`, передаётся по имени); узел снимает со стека
ответы своих детей — последний ребёнок сверху (`ChildrenFirst::takeAnswer` / `takeAnswers`).
Запись и снятие — общий шаблон `ChildrenFirst` (`semantic/flow/children_first`), узлом может быть
что угодно: выражение, тип, инструкция с метками (`ReturnPart`), условие со знаком
(`SignedCondition`).

**Ранний выход:**
1. не раскладывать детей, если ответ ясен по самому узлу (`x as T` — детей нет);
2. правило «всё или ничего» — остановить весь цикл на первой неудаче (как выше): запись идёт
   слева направо, как рекурсия, поэтому останавливаемся на той же части, и побочные действия
   происходят в том же порядке.

Смешанные чистые функции (`alwaysReturns`: блок — «хотя бы одна», `if` — «обе») — машина без
остановки, ответ тот же. Сведения сверху вниз (метки, глубина, знак) — в раскладке рядом с узлом.

Если детей узла можно узнать только по ходу (нужен `this`, состояние, побочные действия —
`substituteAt`, `portable`, `literalExpectation`), раскладку заранее не пишут: стек шагов
«войти / собрать» (`Union`), «войти» кладёт «собрать» и детей, «собрать» снимает ответы детей.
Если ребёнок у узла один и он не того же вида (члены объединения — не объединения), это
приём 4, а не машина (`designConstructor`, `keysOf`).

**Отвергнуто:** словарь «узел → ответ»; кадры «узел + следующий ребёнок + накопленный ответ» с
тремя функциями на вид узла (`startFrame/absorbChild/nextNeededChild`).

## 8. Известный алгоритм — под своим именем, на стеке кадров

**Признак:** граф, у алгоритма есть имя (Тарьян — группы взаимно вызывающих функций).

**Стало:** кадр и метод названы по алгоритму, тело цикла читается как алгоритм, ветки — в
функциях с именами, без ссылок на элемент растущего вектора:

```cpp
void CallCycles::tarjanSearch(int start, CycleSearch &search) {
  std::vector<TarjanFrame> frames;
  CallCycles::enter(start, search, frames);
  while (!frames.empty()) {
    int caller = frames.back().node;
    std::optional<int> callee = CallCycles::takeNextCall(frames.back(), search);
    if (callee.has_value()) {
      CallCycles::followCall(caller, *callee, search, frames);
    } else {
      this->finishTop(search, frames);
    }
  }
}
```

**Смотреть:** выбирать алгоритм, который сохраняет порядок результата (Тарьян, не Косарайю:
`inferCycle` идёт по членам группы по порядку).

## 9. Обход с входом и выходом из областей — лента событий

**Признак:** обход открывает и закрывает области видимости, по ходу решает «дальше не смотрим».

**Стало:** обход пишет плоскую ленту событий (`Union` видов: войти в блок, выйти, объявить имя,
значение…), у «войти» — номер парного «выйти». Сканер — один цикл:

```cpp
size_t at = 0;
while (at < tape.size()) {
  at = this->applyStep(tape[at], at + 1, scan);
}
```

`applyStep` — `switch` по `kind()`, строка на вид; обработчики одной формы: событие и номер
следующего шага на входе, номер шага, с которого продолжать, на выходе. «Дальше не смотрим» —
вернуть номер после парного «выйти».

**Где (пример):** `tmp/destination_events_example.cpp` для `DestinationScanner::scanDestinations`.

**Когда шаги зависят от хода:** в `DestinationScanner` «куда кладём» (тип из `peekType`,
параметры вызова) и «дальше не смотрим» (`for`: имя объявлено в init) узнаются только по ходу,
поэтому лента не пишется заранее: шаги кладутся на стек по мере обхода (`ScanRun`, 13 видов),
порядок тот же, что у рекурсии. Шаг, которому нужен результат предыдущих детей, — отдельный вид
(`AssignValue`: тип цели после обхода цели).

## 10. Два типа сразу — список целей только с «все» (проверяется)

**Признак:** отношение двух типов (`isImplicitlyConvertible`), смешаны «все» (объединение слева)
и «хотя бы один» (объединение справа), рекурсия кольцом через другие функции.

**Идея:** в tz варианты объединения различимы при выполнении (`UnionSlots::unionProblem`), значит
для варианта слева пара «того же вида» справа единственна (массив, функция, итератор, `Promise`,
`Json`; `Result` в объединение не входит), а остальное проверяется без спуска. Остаётся один
список целей с «все» и выходом на первом «нет», без отката и кольца:

```cpp
bool TypeRelations::isImplicitlyConvertible(const Type *from, const Type *to) {
  std::vector<ConvertGoal> goals = {ConvertGoal{.from = from, .to = to}};
  while (!goals.empty()) {
    ConvertGoal goal = goals.back();
    goals.pop_back();
    if (!TypeRelations::fitsVariants(goal, goals)) {
      return false;
    }
  }

  return true;
}
```

**Статус:** схема в `tmp/convertible_simplified_example.cpp`; надо разложить ~30 правил и
проверить особые случаи (`Json`, объединения с пометкой tagged, параметры типа).
Вложенный запуск на каждого кандидата «хотя бы один» рекурсию не убирает — только прячет.

## 11. Проверка (большое кольцо) — машина со стеком задач

**Признак:** рекурсия по кругу через много частей: `checkExpr` → части → `checkExpr`, проверка ↔
разрешение типов ↔ вывод результата функции.

**Стало:** у машины три стека — `tasks` (шаги с именами), `checked` (проверенные узлы: ребёнок
кладёт себя, родитель в шаге «готово» снимает и пишет в свои поля), `flows` (сохранённые потоки,
вложенно, как скобки). Цикл — «взять задачу, выполнить»; разбор — `switch` по `kind()`.

```cpp
void CheckMachine::pushCallArgs(const CallArgs &task) {
  task.call->callee = this->takeChecked();
  CallChecker::ResultCalleeCallable callable = this->callChecker->calleeCallable(task.call);
  if (callable.isOk()) {
    this->pushArgChecks(task.call);
  } else {
    this->failExpr(task.call, callable.error().message);
  }
}
```

**Правила:**
- задачи не хранят адресов в дереве (`Expr **`): в дерево пишет только сам узел, в своём шаге;
- следующий шаг кладётся только после удачи предыдущего; ранний выход — `failExpr` (сообщить и
  положить узел-ошибку), отменять нечего;
- «выйти» (область видимости, тело функции, заглушённые ошибки) кладётся вместе с «войти» — под
  задачи детей, выполнится после них всегда;
- решение между детьми — отдельный шаг (`AND_RIGHT`: правая часть `&&` в потоке «левая истинна»);
- пробная проверка — пара задач «начать пробу» / «проба готова», без вложенного запуска машины;
- нужное по требованию (тип результата другой функции, объявление раньше времени) — шаг кладёт
  себя обратно, а поверх — задачу «разрешить»; защита от зацикливания — пометки на символах;
- задачи маленькие (указатели и флаги), `Flow` — на своём стеке; листья проверяются сразу.

**Переход:** по видам узлов; ещё не переведённый вид машина выполняет старой функцией внутри
задачи. Пример — `tmp/check_machine_example.cpp`.

## 12. Наследники класса — список и `for`

**Признак:** рекурсия по `cls->children` (перепривязать наследников, найти наследника, который
переопределяет метод).

**Стало:** наследники одним списком — `ClassTree::descendants(cls)` (в глубину, порядок как у
рекурсии: от него зависят «первый найденный» и нумерация `id/lastId`), все классы в порядке
дерева — `ClassTree::treeOrder`; вопрос — `for` с ранним `return`. Обход с отсечением
(«уже помечен — детей не смотрим», `markReflectMethods`) — стек с проверкой при снятии.

## 13. Разрешение по требованию — стек кадров внутри функции

**Признак:** `resolveX(decl)` с пометками «готово» / «разрешается», зовётся из многих мест
посреди их работы и по ходу разрешения зовёт себя для того, что нужно телу (`resolveAlias`,
`resolveEnum`, `exportsOf`, `completeClass`).

**Стало:** сигнатура та же, вызывающие не меняются. Внутри — обход в глубину на своём стеке:
кадр = «объявление + что нужно телу + что смотреть следующим». Начало (пометка «разрешается»,
заготовка, переключение модуля) — при входе в кадр, тело и конец — при выходе. Когда тело
разрешается, всё нужное уже готово, и вложенный вызов из резолвера отвечает сразу.

```cpp
const Type *TypeDeclarer::resolveAlias(TypeAliasDecl *alias) {
  if (alias->resolved != nullptr) {
    return alias->resolved;
  }
  if (alias->resolving) {
    return this->resolvingAlias(alias);
  }
  std::vector<AliasFrame> frames;
  this->startAlias(frames, alias);
  while (!frames.empty()) {
    TypeAliasDecl *needed = TypeDeclarer::takeUnresolvedAlias(frames.back());
    if (needed != nullptr) {
      this->startAlias(frames, needed);
    } else {
      this->finishAlias(frames);
    }
  }

  return alias->resolved;
}
```

**Правила:**
- нужное собирается в том порядке, в каком его встретит тело — тогда совпадает и порядок, и то,
  кого кольцо пометит (`recursive` у псевдонима, ошибка у enum);
- собирать по маршруту только там, где тело точно идёт по всем частям слева направо;
  недобрать можно (сработает старый вложенный вызов), лишнего брать нельзя;
- то, что нарочно откладывается (псевдонимы с `typeof`), не брать;
- что «разрешается» выше по стеку — не брать: его обработает тело, как сейчас;
- переключение модуля — при входе, возврат — при выходе: вложенно, как скобки;
- если в кольце виден недоделанный результат (часть экспортов модуля, уже посчитанные члены
  enum'а) — тело не делается целиком при выходе: оно делится на шаги, у каждого шага своё нужное,
  и оно разбирается прямо перед шагом. Цикл тот же: «шагу нужно неготовое — войти в него, нет —
  сделать шаг». Шаги — список `Union` при входе (`exportsOf`) или один член за шаг (`resolveEnum`);
  проверки, которые сейчас идут до нужного (повтор имени члена), — при входе в шаг.

**Смотреть:** в программе с ошибками порядок сообщений может измениться (тело бросает работу
на первой ошибке, а нужное уже собрано); посторонняя работа тела (экземпляры обобщённых классов)
идёт после нужных псевдонимов, а не между ними. Зависимости, не видные по именам (`typeof C.m`,
тело обобщённого псевдонима, условные типы, значения по умолчанию, тела `init`), остаются
вложенным вызовом до машины проверки (11). Примеры — `tmp/alias_frames_example.cpp` (тело целиком),
`tmp/exports_frames_example.cpp` и `tmp/enum_frames_example.cpp` (тело по шагам — порядок и
