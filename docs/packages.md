# Пакеты

Решения, принятые 24 октября 2026 года. Шаги 1–3 плана сделаны 24 октября, из шага 4 — `ms` и `uuid`;
что осталось — в конце, в разделе «План реализации».

## Коротко

- Пакет — исходники на TS, которые проходят правила tz. Компилируются вместе с программой, как
  в Go: в exe попадает только используемое.
- Чужие библиотеки как есть не компилируются. Самые популярные постепенно адаптируем под tz;
  механическую часть делает `tz port`.
- Откуда: JSR и git. npm и своего реестра нет.
- `import { z } from "zod"` — как в TS. Зависимости — в `tz.json`, точные версии — в `tz.lock`.

## 1. Почему не npm

**В npm почти нет исходников на TS.** Туда публикуют скомпилированный JS и `.d.ts` (одни типы,
без кода), а JS без типов в быстрый машинный код не переведёшь. Из десяти популярных TS-библиотек
(zod, hono, date-fns, neverthrow, ms, uuid, ky, valibot, remeda, ts-pattern) исходники `.ts`
лежат в пакете npm только у zod.

Исходники есть в JSR (jsr.io — реестр, куда публикуют именно TS: 22 800 пакетов, среди них zod,
hono, valibot, remeda, ts-pattern, стандартная библиотека Deno) и на GitHub — почти у всех.

**Но и исходник на TS не проходит правила tz.** Строки исходников (без тестов, подсчёт поиском —
примерно):

| Пакет | строк | `any` | `as` | `===` | `null` | `export default` | `get` / `set` | `prototype` |
|---|---|---|---|---|---|---|---|---|
| zod | 30 398 | 776 | 905 | 1268 | 414 | 187 | 78 | 71 |
| date-fns | 77 534 | 1008 | 238 | 512 | 67 | 0 | 0 | 17 |
| valibot | 25 878 | 111 | 138 | 212 | 250 | 0 | 0 | 12 |
| hono | 19 458 | 290 | 426 | 699 | 190 | 8 | 18 | 7 |
| remeda | 9 004 | 27 | 53 | 195 | 28 | 0 | 3 | 9 |
| ky | 3 430 | 27 | 82 | 180 | 27 | 36 | 3 | 9 |
| ts-pattern | 2 637 | 161 | 17 | 42 | 10 | 5 | 0 | 7 |
| uuid | 957 | 0 | 0 | 18 | 5 | 46 | 0 | 0 |
| neverthrow | 779 | 10 | 9 | 0 | 0 | 0 | 0 | 0 |
| ms | 184 | 0 | 2 | 4 | 0 | 0 | 0 | 0 |

- `===`, `null`, `export default` заменяются автоматически.
- `any` и `as` — места, где автор сказал компилятору «поверь мне». tz так не может: ему нужен
  точный тип, чтобы разложить данные в памяти. Их правит человек.
- `get` / `set` и прототипов в tz нет ([objects.md](objects.md)) — тоже руками.

Полную совместимость (`any` и `as` с проверками при работе, прототипы, геттеры) не делаем: это
свой движок JS внутри exe — медленно и большие exe.

## 2. Адаптация популярных библиотек

- Самые нужные библиотеки адаптируем под tz сами, постепенно. API — как у оригинала: код с
  `import { z } from "zod"` работает без правок.
- Адаптированный пакет — код TS, только строже, в файлах `.tz` ([modules.md](modules.md),
  раздел 2): node, Deno и Bun его не запускают. Публикуется в JSR под общей областью проекта
  (например, `@tz/zod`); `tz add zod` находит его сам.
- `tz port <пакет>` — инструмент для этого: скачивает исходник, сам заменяет `===` на `==`,
  `null` на `undefined`, `export default` и `import * as` на имена, а `any`, `as`, `get` / `set`
  и прототипы выписывает списком с подсказками. Копия — файлы `.tz`: `a.ts` становится `a.tz`,
  импорты `"./a.ts"` и `"./a.js"` — `"./a.tz"`.
- Что из языка нужно до адаптации:

  | Пакет | Нужно |
  |---|---|
  | ms | почти готов: два `as` |
  | uuid | байтовые массивы и `crypto.getRandomValues` |
  | zod, valibot | условные типы ([generics.md](generics.md), раздел 10) |
  | hono | HTTP во встроенной библиотеке |
  | date-fns | `Date` ([date.md](date.md)) |

  neverthrow больше не нужен: `Result`, `ok`, `err` встроены в язык, но без `safeTry`,
  `ResultAsync` и `fromThrowable` — с neverthrow tz не совместим ([errors.md](errors.md)).
  Перенесённые пакеты, которые бросают исключения (zod, hono, uuid…), при переносе
  переписываются на `Result` ([errors.md](errors.md), шаг 2).

## 3. Откуда брать

- **JSR** — основной источник: `"zod": "jsr:@tz/zod@^4"`.
- **git** — для того, чего в JSR нет: репозиторий и тег версии,
  `"lib": "github:user/repo@v1.2.0"`, или любой адрес git.
- **npm** — нет: в нём нет исходников.

## 4. Проект

```json
// tz.json
{
  "dependencies": {
    "zod": "jsr:@tz/zod@^4",
    "uuid": "github:uuidjs/uuid@v14.0.3"
  }
}
```

- `tz add zod`, `tz remove zod`, `tz update` — правят `tz.json` и `tz.lock`.
- `tz.lock` — точные версии и хеши исходников: у всех собирается одно и то же.
- Исходники скачиваются в общий кэш на машине; сборка без сети идёт из кэша. `node_modules` и
  `npm install` не нужны.
- Каждый пакет — в одной версии на программу. Если двум зависимостям нужны несовместимые
  версии одного пакета — ошибка с объяснением, кто чего хочет.

## 5. Сборка

- Пакеты компилируются из исходников вместе с программой: в exe — только то, что используется,
  generics раскрываются под типы программы ([generics.md](generics.md)).
- Правила для пакетов те же, что для программы: отдельного «мягкого» режима нет.
- Разобранные и проверенные пакеты кэшируются, чтобы повторная сборка была быстрой.
