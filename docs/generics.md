# Generics

Решения, принятые 22–23 октября 2026 года, и поправка 26 октября: `T extends number` — только
`double`, ограничения «любое число» нет ([numbers.md](numbers.md)). Шаги 1–5 плана сделаны 24–25 октября; порядок остальных работ
описан в конце, в разделе «План реализации». Объекты и классы, на которые generics опираются,
описаны в [objects.md](objects.md).

## Коротко

- Для каждого представления типа в памяти — своя копия кода, без упаковки значений. Своя копия
  на конкретный тип — только если тело обращается к его полям или методам.
- Тело обобщённой функции проверяется один раз, как в tsc. Наши правила, которые строже TS,
  проверяются при подстановке типа, и ошибка показывается у вызова.
- Аргументы типа выводятся как в TS. Если вывести не из чего — ошибка: типа `unknown` нет.
- `T extends { name: string }` означает «есть хотя бы эти поля». `T extends number` — это
  `double`: `number` у нас — другое имя `double`. Обобщённого «любого числа» нет — для разных
  числовых типов пишут перегрузки.
- Обобщённую функцию можно передать как значение там, где тип известен из контекста.
- Есть обёртки над любой функцией (`...args: A`), включая склейку списков `[...A, ...B]`.
- Есть вычисления над типами: `keyof`, `T[K]`, `Partial`, `Pick` и др., свои отображённые типы,
  `typeof` в типах. Условные типы и шаблонные строковые типы — следующим шагом сразу после.
- `as` нет ни в какой форме, `as const` тоже.

## 1. Компиляция: копия на представление

`first<int>` и `first<string>` — разные функции в exe. Каждая устроена так, будто её написали
руками под свой тип: `int` лежит в регистре, `int[]` занимает по 8 байт на элемент, `int32[]` —
по 4, LLVM встраивает и векторизует код.

Копия делается не на каждый тип, а на каждое представление в памяти: `int`, `int32`, `uint8` и
другие целые, `double`,
`boolean`, строка, объект, функция, их варианты с `| undefined`. Все объекты для обобщённого кода
выглядят одинаково (указатель; увеличение счётчика одно и то же, освобождение — через
описание), поэтому `first<User>`, `first<Post>` и `first<Dog>` — одна машинная копия. Своя
копия на тип делается, только если тело обращается к полям или методам `T` (у типов разные
смещения). Маленькие функции LLVM и так встраивает в место вызова.

Почему не одна копия на все типы — замер `sum` по 10 миллионам `int` на нашем аллокаторе:

| Способ | На элемент | Память |
|---|---|---|
| своя копия (так делаем) | 0,10 нс | 38 МБ |
| одна копия + таблица операций (как в Go) | 1,23 нс | 38 МБ |
| одна копия + упаковка (как в Java) | 6,53 нс | 228 МБ |

Кроме того, одна копия на все типы требовала бы одинакового представления у всех `T[]`, то есть
копировать каждый `int[]` при вызове или хранить все массивы упакованными.

Цена — размер exe и время компиляции растут с числом разных представлений. Для обычной
программы это десятки килобайт (hello world сейчас весит 157 КБ).

## 2. Проверка тела

Тело проверяется один раз, как в tsc. `T` внутри — «какой-то тип». С ним можно делать то, что
можно с любым значением: присвоить, передать, вернуть, положить в массив, `==`,
`console.log`, `typeof`. Ошибка в теле показывается в теле, а не у каждого вызова.

Наши правила, которых нет в TS (объект и функцию нельзя превратить в строку, `<` на объектах
нельзя), проверяются при подстановке типа:

```ts
function show<T>(label: string, x: T) { console.log(label + ": " + x) }
show("n", 5)              // ок
show("p", new Dog("Rex"))  // ошибка у этого вызова: show<Dog> превращает x в строку
                          // (строка 1), а объекты в строку не превращаются
```

Если в сигнатуре написано ограничение (`<T extends string | number | boolean>`), ошибка
переезжает в сигнатуру: плохой вызов не подходит под ограничение.

## 3. Вывод аргументов типа

Как в TS:
- из аргументов: `first([1, 2])` — `T = int`; `pair(1, 2.5)` — `T = double` (то же правило,
  что у литерала `[1, 2.5]`);
- стрелки — после остальных аргументов: в `mapAll(xs, x => x * 2)` `T` берётся из `xs`, затем
  `x: T`, затем `U` — из результата стрелки;
- из ожидаемого типа: `const names: string[] = emptyList()`;
- явно: `parse<int32>(s)`; значения по умолчанию: `<T = int>`.

Если вывести не из чего (`const xs = emptyList()`), это ошибка с подсказкой указать тип: в tsc
`T` стал бы `unknown`, а такого типа в tz нет.

## 4. Ограничения

- **`T extends { name: string }`** — «есть хотя бы эти поля». Это единственное место, где тип
  с лишними полями подходит к типу с меньшим набором. Каждая копия знает точную раскладку, и
  `u.name` читается одной загрузкой.
- **`T extends Animal`** — `T` может быть `Animal` или наследником, и результат сохраняет точный
  тип: `loudest([new Dog("Rex")])` возвращает `Dog`, а не `Animal`.
- **`T extends number`** — это `double` (решено 26 октября): `number` у нас — другое имя
  `double`, а любое изменение числового типа пишется явно ([numbers.md](numbers.md)).
  Ограничения «любой числовой тип» нет: функцию для разных чисел пишут перегрузками
  ([overloads.md](overloads.md)) или отдельной функцией на тип.
  ```ts
  function maxOf<T extends number>(a: T, b: T): T { return a > b ? a : b }
  maxOf(1.5, 2.5)          // ок: double
  maxOf(1, 2)              // ошибка: int — не number; приведи или напиши перегрузку для int
  class Stats {
    static max(a: int, b: int) { return a > b ? a : b }
    static max(a: double, b: double) { return a > b ? a : b }
  }
  ```
- **Объединения в ограничениях** (`T extends string | int`) — копия на каждый вариант.

## 5. Обобщённые типы, классы, интерфейсы

```ts
type Maybe<T> = T | undefined
type Mapper<T, U> = (x: T) => U
class Stack<T> {
  items: T[] = []
  push(x: T) { this.items.push(x) }
  pop(): Maybe<T> { return this.items.pop() }
}
```

`Stack<int>` и `Stack<string>` — разные раскладки (с `int[]` и со `string[]`), но
`x instanceof Stack` верно для обоих, как в JS. `static`-члены общие для всех `T` и `T`
использовать не могут (как в TS).

## 6. Обобщённая функция как значение

Копию нужно выбрать при компиляции, поэтому:

```ts
lists.map(first)                                    // ок — T из того, куда передаём
const f1: (xs: string[]) => string | undefined = first // ок
const f2 = first<int>                               // ок (так можно и в TS с 4.7)
const f3 = first                                    // ок — просто другое имя для first
function applyBoth(f: <X>(x: X) => X) { ... }       // ошибка: «любая обобщённая функция»
```

Параметр типа «любая обобщённая функция», которую внутри вызывают с разными типами, потребовал
бы одной копии кода на все типы. В TS-коде он встречается редко.

## 7. `typeof` внутри обобщённого кода

`if (typeof x == "string")` сужает `x` до `string`, как в TS. В каждой копии ответ известен при
компиляции, и лишняя ветка выбрасывается: `describe<int>` не содержит проверки вообще.

## 8. Рекурсия

Обычная рекурсия `f<T>` → `f<T>` — одна копия, хвостовые вызовы гарантируются, как сейчас.
Рекурсия, которой нужно бесконечно много копий (`f(x: T)` вызывает `f([x])`, дальше `T[][]`,
…), — ошибка компиляции.

## 9. Списки параметров: обёртки над любой функцией

`A extends unknown[]` — «список типов параметров какой-то функции» (кортеж). `unknown[]` пишется
только в ограничении, как такового типа `unknown` нет.

```ts
function logged<A extends unknown[], R>(name: string, fn: (...args: A) => R) {
  return (...args: A): R => { console.log("→ " + name); return fn(...args) }
}
const loggedAdd = logged("add", add)   // A = [int, int], R = int
```

- **В копии список становится обычными параметрами:** для `A = [int, int]` обёртка — это
  `(a0: int, a1: int) => { ...; return fn(a0, a1) }`. Кортеж создаётся, только если `args`
  используют как значение (`args.join(",")`), и даже тогда компилятор может обойтись без него.
- **С `args` можно:** передать дальше (`fn(...args)`, `console.log(...args)`); `args.length`
  (в копии — константа); `args[0]`; `for...of` (в копии разворачивается по параметрам). Каждый
  элемент — «какой-то тип», как голый `T`.
- **Сохраняются** необязательные (`A = [string, string?]`) и rest-параметры (`A = int[]`).
  Правило про `map(parseInt)` действует и сквозь обёртку.
- **Обёртка над методом** (`logged("inc", c.inc)`) работает: метод уже привязан к объекту.
  Декоратору метода нужны явный параметр `this: T` и `fn.call(this, ...)` — это в шаге
  декораторов.
- **Склейка списков:** `[X, ...A]` (убрать или добавить первый параметр), `[...A, X]`
  (последний), `[...A, ...B]` (частичное применение):
  ```ts
  function partial<A extends unknown[], B extends unknown[], R>(fn: (...args: [...A, ...B]) => R, ...head: A) {
    return (...tail: B): R => fn(...head, ...tail)
  }
  const plus3 = partial(add3, 1, 2)   // A = [int, int], B = [int]; в exe: (c: int) => add3(1, 2, c)
  ```
  Вывод: список с одной неизвестной частью делится однозначно. Если частей две, сначала
  выводится то, что видно из других аргументов (как стрелки выводятся после остальных
  аргументов), потом остаток. Если поделить нельзя — ошибка с подсказкой указать типы явно.
- **Кортежи как типы списков** — например, события: `emit<K extends keyof Events>(name: K,
  ...args: Events[K])`.

## 10. Вычисления над типами

Существуют только при компиляции; в exe всё уже конкретное.

**В основном шаге generics:**
- `keyof T` (`keyof User` — `"id" | "name" | "email"`) и `T[K]` (`User["name"]` — `string`).
  `get<T, K extends keyof T>(o: T, k: K): T[K]`: в exe `k` — номер поля, чтение — по таблице
  смещений; если `k` известен при вызове — просто чтение поля.
- Готовые утилиты: `Partial`, `Required`, `Readonly`, `Pick`, `Omit`, `Record`, `NonNullable`,
  `ReturnType`, `Parameters`. Типы точные, поэтому `Pick<User, "id" | "name">` — новый тип, и
  значение для него — новый объект: `const p: Preview = user` — ошибка (лишнее поле).
- Свои отображённые типы: `{ [K in keyof T]: (value: T[K]) => boolean }`, с модификаторами `?`,
  `readonly`, `-?`, `-readonly`.
- `typeof` в позиции типа: `type Config = typeof defaults`, `keyof typeof defaults`.

**Следующим шагом, сразу после:**
- тип `never`, условные типы `T extends X ? A : B`, `infer`, распределение по объединениям;
  построенные на них `Exclude`, `Extract`;
- операции над кортежами в типах («первый элемент», «всё кроме первого»);
- шаблонные строковые типы (`` `on${Capitalize<K>}` ``) и переименование ключей в отображённых
  типах (в TS для него пишут `as` внутри типа; как это выглядит у нас — решим на этом шаге).

`as` нет ни в какой форме, в том числе `as const`: литеральные типы кортежей пишутся руками
(`const dirs: readonly ["up", "down"] = ["up", "down"]`).

## План реализации

На каждом шаге: тесты `tests/run` (с `// same-as-node`, где поведение совпадает с JS), ошибки в
`tests/errors`, прогон с `-O0` и `-O2` под `TZ_CHECK_LEAKS=1`, обновление README.

1. **Обобщённые функции и псевдонимы типов** (сделано). Синтаксис `<T>`, явные аргументы, значения по
   умолчанию; вывод (аргументы, стрелки после остальных, ожидаемый тип); копии по
   представлению; проверка тела с непрозрачным `T`; проверка наших правил при подстановке;
   `typeof` внутри обобщённого кода; ошибка на бесконечную рекурсию копий; функции как значения;
   `T extends number` и объединения в ограничениях. От объектов не зависит — этот шаг можно
   делать и до них.
2. **Generics и объекты** (сделано). Ограничения с полями и классами, своя копия на тип при обращении к
   полям и методам `T`, обобщённые классы и интерфейсы. После шагов 1–4 плана объектов.
3. **Списки параметров** (сделано). `...args: A`, всё, что можно с `args`, сохранение необязательных и
   rest-параметров, склейка `[X, ...A]`, `[...A, X]`, `[...A, ...B]` и вывод их частей. Нужны
   кортежи (шаг 2 плана объектов).
4. **Вычисления над типами, основное** (сделано). `keyof`, `T[K]`, готовые утилиты, свои отображённые
   типы, `typeof` в типах.
5. **Вычисления над типами, остальное** (сделано). `never`, условные типы, `infer`, `Exclude` / `Extract`,
   операции над кортежами в типах, шаблонные строковые типы.
6. **Поправка 26 октября** (сделано 27 октября; с [numbers.md](numbers.md), шаг 1): `T extends number` — только
   `double`; копии на новые целые типы (`int` — 64 бита, `int8` … `uint64`). Целый литерал
   там, где параметр типа ограничен `double`, подстраивается: `half(7)` — `double`.

После generics — декораторы.
