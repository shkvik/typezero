# Мелочи языка

Решения, принятые 23 октября 2026 года. Пока ничего из этого не реализовано: порядок работ — в
конце, в разделе «План реализации».

## Коротко

- Истинность — как в JS, но без чисел. В условии можно `boolean`, строку и «объект или
  `undefined`»; число — ошибка с подсказкой (`!= 0`, `??`). Присваивание в условии — ошибка.
- `let` без значения — с явным типом: `let msg: string`.
- Сравнение одно — `==` и `!=`; `===` и `!==` — ошибка с правкой.
- Число + строка — ошибка: текст собирают шаблоном. `sort()` у чисел без функции — ошибка.
  `bigint` нет, вместо него — `decimal` ([decimal.md](decimal.md)).
- Синтаксис JS, которого не хватало: `void`, `debugger`, `5.`, `-"3"`, шаблоны с тегом. `in` и
  `delete` у массивов — ошибки с подсказками.

## 1. Истинность

Условие — это `if`, `while`, `do...while`, `for(;;)`, `?:`, а также `!x`, `x && y`, `x || y`,
`x ||= y`, `x &&= y`, `Boolean(x)` и `filter(Boolean)`.

| Тип | В условии | Ложь |
|---|---|---|
| `boolean` | можно | `false` |
| `boolean \| undefined` | можно | `false`, `undefined` |
| `string` | можно | `""` |
| `string \| undefined` | можно | `""`, `undefined` |
| объект, массив, функция с `\| undefined` | можно: «есть или нет» | `undefined` |
| объект, массив, функция без `undefined` | ошибка: всегда правда | — |
| число (`int`, `long`, `double`…), с `undefined` и без | ошибка | — |
| `unknown`, `T` без ограничений | ошибка: там может оказаться число | — |

```ts
if (user) send(user.email)          // User | undefined: «есть ли»; внутри user: User
const title = nick || "аноним"      // string | undefined: "" тоже заменится
if (!name) return                   // string: пустая строка

if (count) ...                      // ошибка → count != 0
const t = timeout || 1000           // ошибка → timeout ?? 1000
while (stack.length) stack.pop()    // ошибка → stack.length > 0
if (items) ...                      // ошибка: массив есть всегда → items.length > 0
if (check) ...                      // ошибка: функция есть всегда → check()
if (level = 0) ...                  // ошибка → level == 0
```

- **Почему без чисел.** У числа `0` — обычное значение (порт, скидка, таймаут), а `NaN` тоже
  ложь. `port || 3000` теряет ноль, `items.length && "список"` даёт `0`,
  `[0, 1, 2].filter(Boolean)` выбрасывает ноль. Почти всегда имели в виду `??` или `!= 0`. У
  объекта и строки JS делает то, что хотят: «есть ли» и «пустая ли».
- **Подсказка зависит от типа**, её текст вставляется как есть:
  - `int | undefined` — проверяли «есть ли»: `!= undefined`, `??`, `??=`;
  - `int` — проверяли «не ноль»: `!= 0`, у `.length` — `> 0`;
  - `double` — там ещё и `NaN`, поэтому подсказка предлагает выбрать: `!= 0`, `> 0` или
    `!Number.isNaN(x)`.
- **Всегда правда — ошибка**: массив, объект, функция без `| undefined`, в том числе
  `items || []`. И после сужения: если выше стоит `if (!user) return`, то дальше `if (user)` —
  ошибка. tsc ловит только функцию без скобок (TS2774).
- **Generics и `unknown`.** `T` без ограничения может оказаться числом, поэтому
  `x || fallback` — ошибка с подсказкой `x ?? fallback`: иначе `firstOr([0, 5], 9)` дало бы `9`.
  `T extends { name: string }` — объект, проверка «есть или нет» разрешена. `unknown` сначала
  проверяют: `!= undefined`, `typeof`.
- **Сужение — как в TS**: внутри `if (user)` у `user` тип `User`, после `if (!nick) return` у
  `nick` — `string`. `filter(Boolean)` убирает `undefined` из типа:
  `(string | undefined)[]` → `string[]` (tsc так не умеет).
- **Результат `&&` и `||`** — как в JS: одно из значений, не обязательно `boolean`.
  `user && user.name` — `string | undefined`.
- **Присваивание в условии — ошибка**, и в двойных скобках тоже: `if (level = 0)` →
  `level == 0`, `while (line = readLine())` → `while ((line = readLine()) != undefined)`.
  Первый цикл к тому же остановился бы на первой пустой строке.
- **Что остаётся из JS**: `"0"` и `"false"` — правда. При `DEBUG=false`
  `if (process.env.DEBUG)` сработает. Это про данные, а не про язык: `DEBUG == "1"`.
- **В машинном коде** строка — «длина ≠ 0», объект или `undefined` — «указатель ≠ 0», без
  вызовов.
- **Цена**: в TS-коде придётся править только числа — `if (arr.length)`, `if (!count)`,
  `opts.n || 10`.

## 2. `let` без значения

```ts
let msg: string                   // тип пишут явно
if (ok) msg = "готово"
else msg = "ошибка"

let found: string | undefined     // может остаться без значения
let total                         // ошибка: напиши тип → let total: int
let empty = undefined             // ошибка: напиши тип → let empty: int | undefined
```

- Из последующих присваиваний тип не выводится (tsc выводит): тип переменной виден там, где
  она объявлена. Так уже работает.
- Ошибка подсказывает тип по присваиваниям ниже — его можно вставить как есть.

## 3. Сравнение: только `==`

```ts
if (x == 0) ...                   // ок
if (name != "") ...               // ок
if (x === 0) ...                  // ошибка → x == 0
if (x == "0") ...                 // ошибка: int и string не сравнивают
```

- В JS `===` появился из-за приведения типов у `==` (`0 == ""` — `true`). В tz `==` ничего не
  приводит: типы с двух сторон должны совпадать, иначе ошибка компиляции. Вторая форма не нужна.
- `===` и `!==` — ошибка с правкой «пиши `==`». В чужом TS-коде таких мест много, правка
  механическая.
- Результат совпадает с node: при одинаковых типах `==` и `===` в JS дают одно и то же.
- `x == undefined` и `x == null` у значения `Json` — как в JS: правда и для `null`, и для
  `undefined`.

## 4. Арифметика

```ts
"Итого: " + total                 // ошибка → `Итого: ${total}`
count + input                     // ошибка → count + Number(input) или `${count}${input}`
s += 5                            // ошибка → s += String(5)
"a" + String(5)                   // ок: строка + строка
[2, 10, 1].sort()                 // ошибка → sort((x, y) => x - y)
```

- **Число или `boolean` + строка — ошибка**, и в `+=` тоже. В JS `10 + "1"` — `"11"`, а
  `count + input`, где `input` пришёл из argv или `readLine`, склеивает вместо сложения.
  Строка + строка — можно; текст собирают шаблоном. Подсказка предлагает оба смысла: сложить
  (`Number(...)`) и склеить (шаблон).
- **`sort()` без функции у массива чисел — ошибка** с подсказкой `sort((x, y) => x - y)`. В JS
  он сравнивает числа как строки: `[2, 10, 1]` → `[1, 10, 2]`. Молча сортировать иначе, чем
  node, хуже: тот же код дал бы другой результат. У строк `sort()` — как есть. То же для
  `toSorted()`.
- **Уже ошибки**, как и в tsc: `"53" - 3`, `"3" * "4"`, `true + 1`, `[1] + [2]`, `n += "1"`.
  `["1", "2", "3"].map(parseInt)` tz тоже ловит (в JS — `[1, NaN, NaN]`), tsc — нет.
- **Как в JS:** `NaN` и `Infinity` у `double` — так устроены дробные числа в процессоре
  (IEEE 754), так же в Go и C#; у `int` их нет. `0.1 + 0.2` — `0.30000000000000004`, для точного
  счёта есть `decimal` ([decimal.md](decimal.md)). `Number("")` — `0`. Строки сравниваются как
  строки: `"10" < "9"`.
- **`bigint` нет:** `10n` и `BigInt(x)` — ошибка с подсказкой: до 9.2·10¹⁸ — `long`, длиннее —
  `decimal`.

## 5. Синтаксис

| Что | Как |
|---|---|
| `void f()` | вычислить и дать `undefined`, как в JS. Нужен для «запустить и не ждать» в async ([async.md](async.md)) |
| `debugger` | остановиться, если программу запустили под отладчиком, иначе ничего |
| `5.`, `5..toString()` | как в JS: `5` и `"5"` |
| `-"3"` | `-3`, как уже работающий `+"3"` |
| `` sql`select ${id}` ``, `` String.raw`C:\dir` `` | шаблоны с тегом — как в JS: функция получает куски строки и значения |
| `1 in arr` | ошибка → `1 < arr.length`: дыр в массивах нет |
| `delete arr[0]` | ошибка → `arr.splice(0, 1)` или `arr[0] = ...` |

`Boolean(x)` — в разделе 1. `typeof x` в типах — в [generics.md](generics.md), шаг 4.

## План реализации

На каждом шаге: тесты `tests/run` с `// same-as-node`, ошибки в `tests/errors`, обновление
README.

1. **Истинность для того, что уже есть**: `boolean`, строки, `T | undefined` у элементов
   массивов, числа (ошибки с подсказками по типу), присваивание в условии, `!`, `&&`, `||`,
   `||=`, `&&=`, `Boolean(x)`, сужение по истинности. Новых зависимостей нет.
2. **Остальное — вместе с типами, к которым оно относится**: объекты и функции с
   `| undefined` и «всегда правда» — с объектами ([objects.md](objects.md), шаги 1 и 3); `T`,
   `filter(Boolean)` с сужением типа — с generics ([generics.md](generics.md), шаг 1);
   `unknown` — с метаданными ([decorators.md](decorators.md), шаг 2).
3. **Подсказка типа у `let` без значения** — по присваиваниям ниже.
4. **Только `==`**: `===` и `!==` — ошибка с правкой; тесты `tests/run` и README переписать на
   `==`. `== null` / `== undefined` у `Json` — вместе с `Json` ([modules.md](modules.md), шаг 3).
5. **Арифметика**: ошибки на число или `boolean` + строку и в `+=` с подсказками обоих
   смыслов; `sort()` / `toSorted()` без функции у чисел. Тесты, которые склеивают текст через
   `+`, переписать на шаблоны. `10n` и `BigInt` — в [decimal.md](decimal.md), шаг 1.
6. **Синтаксис** из раздела 5. Новых зависимостей нет.
