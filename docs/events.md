(раздел 4, [errors.md](errors.md), раздел 5). 3 ноября: события без утечек — одно значение в

плана сделаны 24 октября, шаг 6 — 27 октября, шаги 7–12 — 3 ноября (кроме `EventTarget` и
прослеживания слушателя-параметра); что осталось — в конце, в разделе «План реализации».
11 ноября: карту без явного типа дают `emit` модуля, где эмиттер создан, программа проверяется за
один проход (раздел 2).

## Коротко

- `node:events` — как в node: `EventEmitter`, `once()`, `on()`, но без утечек (раздел 6).
  `EventTarget`, `Event`, `CustomEvent` — как в браузере.
- Событие несёт одно значение: `emit("message", { from, text })`. Встроенные тоже:
  `socket.on("close", ({ code, reason }) => …)`.
- Типы событий компилятор выводит сам — из `emit` в модуле, где эмиттер создан. Подписка на
  событие, которое никто не шлёт, — ошибка компиляции (обычно это опечатка). Явная карта
  событий — можно; обязательна, если имя события берётся из переменной.
- Слушатель — метод объекта (`this.send`) или стрелка, которая захватывает один внешний объект
  или ничего. Этот объект — получатель: эмиттер держит его слабо. Получатель освобождён — его
  подписки ушли; `off` можно, но не нужно.
- Ждать событие своего эмиттера (`once`, `for await … of on`) в функции — только с `timeout`.
- async-слушатель разрешён: он сам считается «запустить и не ждать». Слушатель, который
  возвращает `Result`, — ошибка: его никто не прочитает.
- Событие `error` без исключений: подписался на события объекта, который может испустить
  `error`, — подпишись и на `error`; свой объект шлёт `error`, а слушателя нет нигде — ошибка
  компиляции. `once()` отдаёт `Result`.
- `setInterval` — по тем же правилам, что подписка (раздел 7).
- Код — перенос `lib/events.js` из node: порядок вызова, служебные события и тексты
  предупреждений совпадают — кроме разделов 6–7.

## 1. Как пишут

```ts
import { EventEmitter, once } from "node:events"

const bus = new EventEmitter()
bus.on("user", user => console.log(user.name))   // user: User — выведено из emit ниже
bus.once("user", user => console.log("первый"))
bus.emit("user", ann)                            // слушатели вызываются сразу, по порядку
bus.off("user", handler)
const r = await once(server, "listening")        // дождаться события: Result<[port: int], …>
if (r.isErr()) return r                          // раньше пришло error
const [port] = r.value
```

`EventEmitter` — основа процессов ([process.md](process.md)), потоков node и `node:http`.

## 2. Типы событий

**Выводятся из `emit`.** Для каждого места, где создаётся `new EventEmitter()` (и для каждого
класса-наследника), компилятор собирает `emit` на объектах оттуда в модуле, где это место
написано, — через переменные и параметры, в функциях и методах. `this.emit` в методах классов,
которые от него наследуют, — тоже, в любом модуле. `bus.emit("user", ann)` — значит, у события
`user` значение типа `User`.

- **Другие модули событий не добавляют** (решено 8 ноября). `emit` оттуда разрешён, но только
  событий, которые шлёт модуль эмиттера, и с тем же значением. Чужое событие — ошибка: «'done'
  is not an event of this emitter: its events are the ones emitted in jobs.tz…». Исправить —
  послать его в модуле эмиттера, например методом класса (`finish() { this.emit("done") }`), или
  написать карту.
- **Один проход** (решено 11 ноября). Программа проверяется один раз сверху вниз. Подписке нужен
  тип события, а `emit` ниже — компилятор заглядывает вперёд: проверяет функции и методы, где
  стоит этот `emit`, и сам `emit` на верхнем уровне модуля (пробно, без ошибок). Если значение в
  таком `emit` использует имена, объявленные ниже подписки, тип не узнать — ошибка с подсказкой
  перенести `emit` в функцию или написать карту.

```ts
bus.on("usr", () => {})          // ошибка: событие usr никто не шлёт (опечатка? есть user)
bus.emit("count", 1)
bus.emit("count", "два")         // ошибка: count шлют с number и со string — оба места в сообщении
bus.emit("message", ann, "hi")   // ошибка: an event carries one value: pass an object —
                                 //         emit("message", { from, text })
```

- **Одно значение или ни одного.** Несколько значений по месту не прочитать — что второе, что
  пятое; объект называет каждое. Событие без значения — `emit("closed")`.
- **Явная карта** — как в `@types/node`: имя события → список его значений, в котором одно
  значение или ни одного. Для своих классов это ещё и документация:
  ```ts
  class Server extends EventEmitter<{ listening: [port: int]; close: [] }> { … }
  const users = new EventEmitter<{ user: [user: User] }>()
  const pairs = new EventEmitter<{ pair: [a: int, b: int] }>() // ошибка: an event carries one value
  ```
  С картой `emit` и `on` проверяются по ней: лишнее событие, не то значение — ошибка.
  `once()` отдаёт этот список, как node: `const [port] = r.value`.
- **Имя из переменной** (`bus.emit(topic, message)`) вывести нельзя — нужна карта:
  `new EventEmitter<{ [topic: string]: [message: Message] }>()`.
- **Встроенные** (потоки, сокеты, WebSocket, UDP) — карты уже описаны, и события, которые в node
  несут несколько значений, у нас несут объект: `socket.on("close", ({ code, reason }) => …)` у
  WebSocket, `socket.on("message", ({ data, from }) => …)` у UDP, `unpipe` у потоков —
  `{ source, hasUnpiped }`. Служебные `newListener` и `removeListener` несут
  `{ event, listener }` (в node — два значения).
- Пока своего языкового сервера нет, tsc в редакторе показывает у слушателей без карты `any`.

## 3. async-слушатель

```ts
bus.on("user", async user => { await save(user) })   // ок
```

`emit` не ждёт слушателей — он всегда «запустил и пошёл дальше», поэтому async-слушатель сам
считается `void save(user)`. Это не ловушка `forEach` ([async.md](async.md), раздел 6): там код
после `forEach` думает, что всё уже сделано, а `emit` никто и не ждёт.

Поэтому и ошибку слушатель разбирает сам. Слушатель, который возвращает `Result` или
`Promise<Result>`, — ошибка компиляции: `emit` результат не читает, и `Err` пропал бы молча
([errors.md](errors.md), раздел 4).

```ts
bus.on("user", async user => save(user))          // ошибка: save возвращает Promise<Result>
bus.on("user", async user => {
  const r = await save(user)
  if (r.isErr()) console.error(r.error)            // ок: ошибка разобрана здесь
})
```

`captureRejections` нет: `Promise` не отклоняется.

## 4. Событие `error`

В node `emit("error", e)` без слушателя `error` бросает `e`, и процесс падает. У нас
исключений нет, поэтому ошибка должна прийти туда, где компилятор заставит её разобрать:

- **Подписался на события объекта, который может испустить `error`** (это видно по его карте
  событий), — подпишись и на `error` этого же объекта, в той же функции, на каждом пути.
  Проверка по путям — как у полей, которые конструктор задаёт на каждом пути.
  ```ts
  const s = createReadStream("a.txt")
  s.on("data", chunk => use(chunk))
  // ошибка: s может испустить error (нет файла, нет прав), а слушателя error нет;
  //         добавь s.on("error", e => …) или читай через for await
  ```
- **Свой `EventEmitter` шлёт `error`, а слушателя `error` у него нет нигде в программе** —
  ошибка компиляции: иначе ошибка пропадает молча. `emit` возвращает, был ли слушатель, —
  можно разобрать самому.
- **Ждать события — `Result`:** `once(emitter, name)` — `Promise<Result<T, E>>`, где `T` — тип
  значения события: `Err`, если раньше пришло `error` (или вышло время, раздел 6). Каждый элемент
  `for await (… of on(emitter, name))` — `Result`.
- `process.on("uncaughtException")` и `process.on("unhandledRejection")` — ошибки: ловить
  нечего.

## 5. Как в node

- Всё API: `on` / `addListener`, `once`, `off` / `removeListener`, `removeAllListeners`, `emit`,
  `prependListener`, `prependOnceListener`, `listenerCount`, `listeners`, `rawListeners`,
  `eventNames`; `once(emitter, name)` — `Promise<Result>`, если у эмиттера есть событие `error`
  или задан `timeout`; `on(emitter, name, { close })` — для `for await`. Опции `signal` нет:
  `AbortSignal` убран 28 октября ([async.md](async.md), раздел 7). Кроме того, что про ошибки
  (раздел 4) и утечки (раздел 6).
- Предупреждения «больше 10 слушателей» нет, `setMaxListeners`, `getMaxListeners` и
  `EventEmitter.defaultMaxListeners` убраны: утечку через подписку исключают правила раздела 6, а
  сотня соединений в одной комнате — обычное дело.
- `this` в слушателе-функции — сам объект; у стрелки — как обычно.
- Имена событий — только строки: своих `Symbol` в tz нет ([iterators.md](iterators.md)).
- `EventTarget`, `Event`, `CustomEvent<T>` (у `detail` — тип `T`) — как в браузере, без опции
  `signal` у `addEventListener`. Правила раздела 6 для `addEventListener` — шаг 14 плана, пока он
  держит слушателя, как в браузере.

## 6. Без утечек

В node эмиттер держит слушателя, а слушатель — всё, что захватил. Забыли `off` — объект живёт,
пока жив эмиттер: соединение, убранное из списка, остаётся висеть на комнате чата, и комната
пишет в мёртвый сокет. Это самая частая утечка node, и сборщик от неё не спасает: до такого
объекта можно дотянуться, это не мусор. У нас эмиттер не держит ни одного объекта программы:
у подписки есть получатель, и подписка живёт, пока он жив.

### Слушатель и получатель

```ts
class Connection {
  private socket: WebSocket

  public constructor(socket: WebSocket, room: Room) {
    this.socket = socket
    room.on("message", this.send)                  // метод: получатель — this
    room.on("closed", () => this.socket.close())   // стрелка захватывает только this
  }

  public send(message: Message) {
    this.socket.send(`${message.from.name}: ${message.text}`)
  }
}

connections.delete(id)   // Connection освобождён — его подписки на room ушли в тот же миг

createServer((request, response) => {
  jobs.on("done", (result) => response.end(result))   // захвачен только response — он получатель
})

room.on("message", (message) => console.log(message.text))   // ничего не захватывает
```

| Слушатель | Получатель | Подписка живёт |
|---|---|---|
| метод, взятый как значение: `x.m` | `x` | пока жив `x` |
| стрелка, захватившая один внешний объект (`this`, `response`) | этот объект | пока он жив |
| стрелка без захватов (глобальные константы — не захват) | нет | пока жив эмиттер |
| что-то ещё | — | ошибка компиляции |

Эмиттер держит получателя слабо, поэтому держать его должен кто-то другой — список соединений,
поле приложения. Сколько живёт получатель, программа и так решает сама; подписка просто живёт
столько же, и второй срок жизни, который надо вести руками через `off`, не появляется.

### Ошибки

```ts
function countMessages(room: Room) {
  let count = 0
  room.on("message", () => count++)
  // ошибка: the listener keeps 'count', which nothing else holds, so nothing tells when the
  //         subscription ends: keep the state in an object and subscribe its method
}

room.on("message", (message) => this.write(request.url, message.text))
// ошибка: the listener captures 'this' and 'request': it may depend on one object only;
//         store what it needs from 'request' in a field of 'this'

new UserCache(db)
// ошибка: the new UserCache is held by nothing, so its listeners would stop at once: store it
```

- **Два внешних объекта** — неясно, чьей жизнью мерить подписку: держать оба слабо — подписка
  молча умрёт с `request`; держать `request` сильно — через него эмиттер может держать и `this`,
  а в методе, который зовут на каждый запрос, подписки снова копятся.
- **Слушатель из параметра или переменной** — пока ошибка у самого `on`: «can't tell what this
  listener captures, so not when its subscription ends; pass a method here». Прослеживать его по
  всей программе, с ошибкой там, где создана функция (`subscribe(room, () => count++)`), — шаг 15
  плана.
- **Код верхнего уровня модуля** вне функций и вне циклов с `await` выполняется один раз — в нём
  захваты любые: такая подписка живёт, пока жив эмиттер, как в node, и копиться ей нечему.
- **Свой эмиттер функции** — локальная переменная этой функции (не параметр и не `this`) или
  `new …` прямо в вызове: захваты тоже любые. Подписка не переживёт эмиттер, а эмиттер — свой у
  каждого вызова: `const socket = new WebSocket(...); socket.on("message", (data) =>
  log(what, data))`.

### Повтор и `off`

Та же пара «код слушателя + получатель» второй раз ничего не добавляет: `room.on("message",
this.send)` дважды — одна подписка (в node — две, и `send` зовётся дважды). Стрелка без захватов
в обработчике запроса добавится один раз, а не по разу на запрос. Сравнение — по коду и
получателю, а не по значению функции. `off("message", this.send)` снимает подписку раньше, если
нужно: `this.send == this.send`. На верхнем уровне и на своём эмиттере функции повтор — как в
node: код там выполняется один раз.

### Ожидания

- **`once` на своём эмиттере в функции — только с `timeout`:** `once(room, "closed", { timeout:
  5000 })`; время вышло — `Err` типа `EventTimeoutError` (`kind: "EVENT_TIMEOUT_ERROR"`,
  `code: "TIMEOUT_ERR"`, `event`, `timeout`). Без него — ошибка: «'room' may never emit this event,
  so the wait may never end». Ожидание эмиттер держит сильно (иначе ждущая задача пропала бы),
  поэтому оно обязано кончиться. На верхнем уровне и на своём эмиттере функции таймаут не нужен —
  как у подписок.
- **Встроенный ввод-вывод кончается сам** — сокеты, потоки, серверы закрывает система или сроки
  сети: `once` на любом эмиттере из библиотеки, кроме самого `EventEmitter`, — без таймаута.
- **Перебор** `for await (const message of on(room, "message", { timeout: 60000 }))` по своему
  эмиттеру — тоже с `timeout`: сколько ждать следующего события; не дождались — перебор кончается
  с `Err`.
- **`Promise.race`** снимает свои ожидания с проигравших (сами проигравшие идут до конца,
  [async.md](async.md)): в node тысяча гонок с одним долгим `Promise` оставляет в нём тысячу
  записей.

### Функции «одна на объект» — не подписки

`createServer(handler)`, `server.listen(port, callback)`, `http.request(options, callback)`,
`exec(command, callback)` — обычные параметры, захваты в них любые: такую функцию держит один
объект, она одна на объект и уходит вместе с ним или после одного вызова — копиться нечему.
Правило получателя висит только на методах подписки (`on`, `once`, `addListener`,
`prependListener`, `prependOnceListener`) и на `setInterval`.
Библиотека хранит такие функции в полях, а не подписывает их через свой же `on`.

### Как устроено

- Значение-функция в tz — `{ code, env }`. У метода, взятого как значение, `env` — сам объект.
  Стрелку, которая захватывает один объект, компилятор собирает так же: `env` — этот объект, код
  получает его первым параметром. Вид функции (метод, без захватов, один объект) записан в
  сведениях рядом с её кодом.
- Запись подписки: `{ код, слабая ссылка на получателя, вид }`. `emit`: получатель жив — вызвать
  код с ним (интринсик `asBoundListener`); умер — запись вычёркивается после этого `emit`, а при
  росте списка вдвое — все мёртвые сразу, так что мёртвых записей не больше, чем живых. Слабая
  ссылка — та же, что у `WeakRef`; типы получателей компилятор отмечает, и их освобождение гасит
  ссылку. Есть ли у объекта слабые ссылки, видно по биту в карте сегмента памяти — освобождение
  объекта без них не берёт общий замок.
- Эмиттер не держит слушателей по сильной ссылке, поэтому группы эмиттера и слушателя не
  сливаются ([objects.md](objects.md), слой 3): после `off` в группе эмиттера ничего не застревает.

### Что остаётся за программой

- Получатель жив, потому что лежит в списке, который никто не чистит, — подписка жива и
  вызывается. Это данные программы.
- Обработчик копит данные в получателе или в глобальном массиве.
- Циклы в данных самого получателя — [objects.md](objects.md), «Известный риск».

## 7. Таймеры

`setInterval` — подписка на время: рантайм держит таймер до `clearInterval`, таймер — функцию,
функция — всё, что захватила. Забытый `clearInterval` в node — та же утечка, что забытый `off`,
только ещё и с работой: 10 тысяч брошенных сессий — 10 тысяч обновлений в минуту. Поэтому у
`setInterval` правила раздела 6.

```ts
class Session {
  public constructor(token: string) {
    setInterval(this.refresh, 60000)                     // получатель — сессия
  }
}
sessions.delete(id)                                      // сессия освобождена — интервал остановлен

createServer((request, response) => {
  setInterval(() => response.write("ping\n"), 1000)     // получатель — response
})

setInterval(() => flushMetrics(), 1000)                 // без захватов — живёт всегда, как в node
```

- **Ошибки** — те же: захват локальных переменных, несколько внешних объектов, объект, который
  держит только его интервал (`new Watch(url)` без записи). Код верхнего уровня модуля — с любыми
  захватами, как в разделе 6.
- **Повтор** той же пары «код + получатель» — тот же интервал: второй вызов возвращает его же, а
  новый период заменяет старый. `feed.start()` дважды — один интервал (в node — два).
- **`clearInterval`** останавливает раньше, как в node. Интервал, чей получатель умер, останавливается
  при ближайшем срабатывании и больше не держит программу.
- **`setTimeout`** срабатывает один раз и уходит — держит функцию сильно, правил нет:
  отложенный `setTimeout(() => this.save(), 1000)` сохранит, даже если объект уже выбросили.
- **Цепочка `setTimeout`, которая ставит сама себя** (`tick() { work(); setTimeout(this.tick,
  1000) }`), — интервал под другим именем: компилятор видит по графу вызовов, что функция таймера
  снова ставит себя же с тем же получателем, и держит получателя слабо. Объект освобождён —
  цепочка остановилась.
