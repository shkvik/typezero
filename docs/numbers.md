# Числа

Решения, принятые 26 октября 2026 года вместе с переделкой ошибок ([errors.md](errors.md)).
Они заменяют прежнее: `int` в 32 бита и `long` в 64, предупреждения о переполнении
([small.md](small.md), раздел 6), `NaN` и `Infinity` как в JS ([small.md](small.md), раздел 4).
План — в конце, в разделе «План реализации».

## Коротко

- `int` — ровно 64 бита на любом процессоре. Точные типы: `int8`, `int16`, `int32`, `uint8`,
  `uint16`, `uint32`, `uint64`. Дробные — `double` (он же `number`), точные десятичные —
  `decimal`. `long` убран.
- Переполнения нет: каждое действие обязано влезать в свой тип, иначе ошибка компиляции.
  Компилятор доказывает это по диапазонам.
- Любое изменение типа — явно, методами: `x.toInt32()`, `x.toDouble()`. Тип результата — тип
  операндов: `int32 + int32` — `int32`.
- Разные целые типы сравниваются по математике: `-1 < 1u` — `true`.
- Побитовые операции — по ширине типа. Счёт с заворотом для хешей — `Bit.Wrap32` и
  `Bit.Wrap64`; повороты, счёт битов, 128-битное произведение — встроенный объект `Bit`.
- `NaN` и `Infinity` в языке нет: компилятор доказывает, что они не получатся.
- Во время работы всё это ничего не стоит: доказательства — при сборке, приведения — ноль или
  одна команда процессора.

## 1. Типы

| Тип | Что это |
|---|---|
| `int` | ровно 64 бита, −9 223 372 036 854 775 808 … 9 223 372 036 854 775 807; его выводит компилятор |
| `int8`, `int16`, `int32` | −128 … 127, −32 768 … 32 767, −2 147 483 648 … 2 147 483 647 |
| `uint8`, `uint16`, `uint32`, `uint64` | 0 … 255, 0 … 65 535, 0 … 4 294 967 295, 0 … 18 446 744 073 709 551 615 |
| `double` (он же `number`) | 64 бита по IEEE 754, 15–17 значащих цифр, без `NaN` и `Infinity` (раздел 10) |
| `decimal` | точное десятичное, растёт без предела ([decimal.md](decimal.md)) |
| `Bit.Wrap32`, `Bit.Wrap64` | беззнаковые 32 и 64 бита со счётом по модулю (раздел 7) |

- **`long` убран:** `int` и так 64 бита. Отдельного `int64` нет — это `int`. Имена без `_t`,
  как в Go: суффикс `_t` в C нужен был только затем, чтобы не столкнуться со старыми `typedef`.
- **Ширина `int` одна на всех процессорах**, а не «по регистру», как в Go и C: программа ведёт
  себя одинаково везде. 32-битный процессор складывает 64-битные числа двумя командами.
- **Литералы:** `5` — `int`, `1.5` и `2.0` — `double`; `const price: decimal = 19.99` —
  точно. Литерал подстраивается под второй операнд и под место, куда его кладут: `x & 0xff`,
  `a * 31`, `const b: uint8 = 200`. Литерал, который в тип не влезает, — ошибка:
  `const b: uint8 = 300`.
- **В объекте и массиве** `int` занимает 8 байт, `int32` — 4, `uint8` — 1.
- **`number` — только `double`**, и в ограничении generics тоже: `T extends number` — это
  `double`, а не «любое число» (решено 26 октября; [generics.md](generics.md) перепишем).
  Отдельного ограничения «любой числовой тип» нет: функцию для разных чисел пишут
  перегрузками ([overloads.md](overloads.md)) или отдельной функцией на тип.
- **Выбор перегрузки без неявных приведений:** переменная подходит только к параметру точно
  своего типа; литерал сначала ищет вариант со своим обычным типом (`5` — `int`, `1.5` —
  `double`), иначе — единственный подходящий; подходят несколько — ошибка с подсказкой
  уточнить литерал. Рейтинга приведений, как в C#, больше нет.
  ```ts
  v.add(5)        // add(k: int) — свой тип литерала
  v.add(5.0)      // add(k: double)
  v.add(n)        // n: int32 — ошибка: варианта для int32 нет, приведи n.toInt() или n.toDouble()
  m.times(2)      // times(double) и times(decimal) — ошибка: напиши 2.0 или явно decimal
  ```

## 2. Переполнение

Каждое действие обязано влезать в свой тип. Не доказано — ошибка компиляции с подсказкой:
проверь вход, считай в более широком типе или возьми `decimal`. Число не растёт и молча не
заворачивается.

```ts
function area(w: int, h: int) {
  return w * h      // ок, если все вызовы передают проверенные или известные числа;
}                   // иначе ошибка: w * h может не влезть в 64 бита

function factorial(n: int) {
  let f = 1
  for (let i = 2; i <= n; i++) f *= i   // ошибка, пока не проверено n <= 20
  return f
}
```

- **Откуда доказательство** — так же, как для других опасных операций
  ([errors.md](errors.md), раздел 7): константы, проверки в `if`, диапазоны по всем вызовам
  функции, известные диапазоны результатов (`xs.length ≥ 0`, маска `x & 0xff` — 0 … 255).
- **Неизвестный диапазон бывает только у того, что пришло снаружи:** разбор текста, JSON,
  байты. Проверка нужна один раз — сразу после чтения.
- **Счётчик с шагом 1** (`requests++`) проходит без ошибки: до конца 64 бит ему 292 года даже
  при шаге в наносекунду.

## 3. Явные приведения

Любое изменение типа пишется явно, как в Go и Rust. В одном действии оба операнда одного
типа, и результат того же типа.

```ts
const a: int32 = 7
const b: int = 5
a + b                    // ошибка: int32 и int — a.toInt() + b
a.toInt() * b            // ок: int
x = x + dx               // ок: int32 + int32 = int32, кладётся обратно без приведения
a * b                    // где a, b: int32 не проверены — ошибка: может не влезть в int32
a.toInt() * b.toInt()    // ок: два int32 в 64 бита влезают всегда
```

- **Методы:**
  - `x.toInt()`, `x.toInt8()`, `x.toInt16()`, `x.toInt32()`, `x.toUint8()`, `x.toUint16()`,
    `x.toUint32()`, `x.toUint64()` — расширение всегда; сужение — с доказательством, что
    значение влезает, иначе ошибка с подсказкой;
  - `x.toDouble()` — из целого с доказательством |x| ≤ 2⁵³, иначе теряется точность;
  - `x.toDecimal()` — всегда точно;
  - из дробного в целое — сначала округление: `Math.trunc(d).toInt()`, `Math.round(d).toInt()`,
    `Math.floor(d).toInt()`, плюс доказательство, что влезает.
- **В `decimal` — тоже явно**, хотя перевод ничего не теряет: `price * qty.toDecimal()` при
  `qty: int`. Литерал подстраивается сам: `price * 3`.
- **`Number(x)`, `String(x)`, `Boolean(x)` остаются**, как в JS. `Number(n)` от целого — то
  же, что `n.toDouble()` (с доказательством |n| ≤ 2⁵³); от строки — `Result` (раздел 9).
- **Индекс массива и число сдвига** принимают любой целый тип, как в Go: `xs[i]` при
  `i: int32` и `x << n` при `n: uint8` — без приведения. Это не действие между двумя числами.
- **Почему тип результата — тип операндов.** Тип выражения виден сразу, ничего не меняется
  молча, и узкие данные остаются узкими: сумма `int32[]` векторизуется по 8 чисел за команду, а
  не по 4. Цена — у узких типов переполнение близко: среднее двух `uint8` считают шире,
  `((c.toInt() + d.toInt()) / 2).toUint8()`. Так же в Rust.
- **Цена во время работы:** расширение — `movzx`/`movsx`, обычно слитое с загрузкой; сужение
  — ноль команд; в `double` — одна `cvtsi2sd`.

## 4. Сравнение

- **Разные целые типы сравниваются по математике,** без приведения: `i < xs.length` при
  `i: int32`; `-1 < 1u` — `true`. В C и C++ `-1 < 1u` — `false`: −1 молча становится
  беззнаковым 4294967295; в C++20 для честного сравнения пришлось добавить `std::cmp_less`.
  Go и Rust сравнение разных типов запрещают — у нас ловушки C нет, и запрет был бы только
  шумом.
- **Целое с дробным — только явно:** `n.toDouble() < 0.5`. C здесь молча переводит целое в
  `double` и теряет точность: `9007199254740993 == 9007199254740992.0` — `true`.

## 5. Деление и остаток

- Делитель доказан ≠ 0, иначе ошибка с подсказкой проверить. У знаковых ещё и не
  `MIN / -1` (−2 147 483 648 / −1 не влезает в `int32`).
- `7 / 2` у целых — `3`. Дробный результат — `a.toDouble() / b.toDouble()`.
- У дробных — раздел 10.

## 6. Побитовые операции

`& | ^ ~ << >> >>>` — по тому же правилу: операнды одного типа, ширина операции — ширина типа
(`int` — 64 бита, `int32` — 32, `uint8` — 8).

- **`<<` — умножение на 2ⁿ:** результат обязан влезть в тип, иначе ошибка. Биты молча не
  теряются; нужен заворот — `Bit.Wrap32`.
- **`>>`** у знакового копирует знак, у беззнакового заполняет нулями. **`>>>`** — только у
  беззнаковых.
- **Число сдвига** доказано в 0 … ширина − 1: `1 << 64` — ошибка, а не 1, как в JS.
- **Маска — доказательство диапазона:** `(x & 0xff).toUint8()` проходит без проверок.
- **Дробное** в побитовой операции — ошибка с подсказкой `Math.trunc`.
- **Идиомы JS `x | 0` и `x >>> 0`** — ошибки с подсказкой: здесь они ничего не заворачивают.
  Нужен заворот — `Bit.Wrap32`; сужение — `.toInt32()`.

```ts
function u32be(b0: uint8, b1: uint8, b2: uint8, b3: uint8) {
  return (b0.toUint32() << 24) | (b1.toUint32() << 16) | (b2.toUint32() << 8) | b3.toUint32()
}
Date.now() >> 10          // ок: 64-битный сдвиг int — верный ответ (в JS — мусор)
```

Код с битами из JS (хеши, crc32, base64, uuid, сжатие) переписывается под эти правила.

## 7. Счёт с заворотом: `Bit.Wrap32` и `Bit.Wrap64`

Хешам, контрольным суммам и генераторам случайных чисел нужен счёт по модулю 2³² или 2⁶⁴, а
обычное переполнение у нас — ошибка. Для этого два типа. Ширина — часть определения алгоритма:
FNV-32, посчитанный по модулю 2⁶⁴, даёт другое число. Знак для хешей не важен, поэтому оба
беззнаковые; 8 и 16 бит — маской.

```ts
function fnv1a32(s: string) {
  let h: Bit.Wrap32 = 0x811c9dc5
  for (let i = 0; i < s.length; i++) {
    h = (h ^ s.charCodeAt(i)) * 0x01000193     // JS: Math.imul(h ^ c, 16777619) >>> 0
  }
  return h.value                               // uint32
}

function fnv1a64(data: Buffer) {
  let h: Bit.Wrap64 = 0xcbf2_9ce4_8422_2325
  for (const b of data) h = (h ^ b) * 0x0100_0000_01b3   // в JS — только через BigInt
  return h.value                               // uint64
}

type Bitboard = Bit.Wrap64                     // фигуры, ушедшие за край, отпадают при сдвиге
```

- **Войти** — литералом по объявлению или `Bit.Wrap32.from(x)` (младшие биты). **Выйти** —
  `h.value`, те же биты.
- **Все действия — по модулю 2ⁿ**, второй операнд — любое целое, результат остаётся
  `Bit.Wrap32`. Поэтому заворот не утекает в обычный счёт: в обычную переменную значение
  попадает только через `.value`.
  ```ts
  const n: uint32 = total + h      // ошибка: это Bit.Wrap32 — (total + h).value
  ```
- **Во время работы** это обычное число и обычные команды процессора, `.value` и `.from` — ноль
  команд.
- `Math.imul` остаётся, как в JS.

## 8. Объект `Bit`

Встроенный глобальный объект, как `Math`, — для того, что не обычная арифметика. Импорт не
нужен.

| Функция | Что делает |
|---|---|
| `rotateLeft32/64(x, n)`, `rotateRight32/64(x, n)` | поворот битов |
| `leadingZeros32/64`, `trailingZeros32/64` | нули слева и справа |
| `onesCount32/64` | число единиц |
| `reverseBytes32/64` | переставить байты (смена порядка байтов) |
| `mul64(a, b)` → `{ hi, lo }` | обе половины 128-битного произведения |
| `add64(a, b, carry)` → `{ sum, carry }`, `sub64` | сложение и вычитание с переносом |

```ts
s[d] = Bit.rotateLeft32(s[d] ^ s[a], 16)     // ChaCha20
const n = Bit.onesCount64(board)
const { hi, lo } = Bit.mul64(a, b)           // Poly1305, X25519
```

- Каждая функция — одна или несколько команд процессора.
- Ширина в имени, как в Go (`bits.RotateLeft32`) и `Math.clz32`, — видна прямо в вызове.
- **Криптография.** `Bit.Wrap32`, `Bit.Wrap64` и `Bit` хватает для ChaCha20, SHA-2, BLAKE2,
  SipHash, Keccak, Poly1305, X25519. Постоянное время выполнения типы не дают: секреты
  сравнивают `timingSafeEqual`, а не `==`, не ветвятся и не делят по ним. Боевую криптографию
  лучше брать из `node:crypto` ([crypto.md](crypto.md)).
- `Math`, `JSON`, `Reflect`, `Intl` не переименовываются; `namespace` из TS и `import * as`
  по-прежнему нет ([modules.md](modules.md)).

## 9. Разбор и байты

- **Разбор целого из текста** (`parseInt`, JSON) даёт не больше 64 бит; длиннее — `Err` с
  подсказкой `decimal`. Мусор — тоже `Err`, а не `NaN`.
- **`parseFloat`, `Number(string)`, унарный `+` от строки** отдают `Result`: `Err` на мусор и на
  число вне ±1.8·10³⁰⁸.
- **Элемент `Buffer`** (`buf[i]`) — `uint8`.
- **`JSON.stringify`** пишет целые больше 2⁵³ точно, всеми цифрами: JSON это разрешает.
  JS-клиент такое число округлит — для идентификаторов лучше строка.
- **`readDoubleLE/BE`, `readFloatLE/BE`** — `Err`, если в байтах лежит `NaN` или `Infinity`.

## 10. Дробные: без `NaN` и `Infinity`

`double` — 64 бита по IEEE 754, но `NaN` и `Infinity` в языке нет: компилятор доказывает, что
они не получатся. Правило то же, что у целых.

| Откуда они берутся | Что нужно |
|---|---|
| `x / y`, `x % y` | `y ≠ 0` и не настолько мал, чтобы частное вышло за ±1.8·10³⁰⁸: `1e10 / 1e-300` — тоже `Infinity` |
| `sqrt` | `x ≥ 0` |
| `log`, `log2`, `log10` | `x > 0`; `log1p` — `x > −1` |
| `asin`, `acos` | −1 … 1 |
| `pow`, `**` | отрицательное основание — только с целым показателем; 0 — с показателем ≥ 0 |
| `*`, `+`, `-`, `exp`, `expm1`, `pow`, `**`, `sinh`, `cosh`, `hypot`, `fround` | результат влезает в ±1.8·10³⁰⁸ |

- **Неизвестный диапазон — только у пришедшего снаружи** (`parseFloat`, JSON, байты). Всё
  остальное компилятор знает: константы, целые, ставшие дробными, `Math.random`, `abs`, `sin`,
  `sqrt`, проверки в `if`, вызовы функции.
- **`Math.clamp(x, lo, hi)`** — встроенная (в JS она пока только предложение). Нужна, когда
  выход за пределы — погрешность, а не ошибка данных:
  ```ts
  Math.acos(ax * bx + ay * by)                    // ошибка: аргумент может выйти за −1 … 1
  Math.acos(Math.clamp(ax * bx + ay * by, -1, 1)) // ок
  ```
  В JS скалярное произведение единичных векторов бывает `1.0000000000000002`, и угол тихо
  становится `NaN`.
- **Уходят:** `NaN`, `Infinity`, `Number.NaN`, `Number.POSITIVE_INFINITY`,
  `Number.NEGATIVE_INFINITY`, `isNaN`, `Number.isNaN`, `isFinite`, `Number.isFinite`. Приём
  `let min = Infinity` заменяет `Math.min(...xs)` (`double | undefined`, пока не доказано, что
  `xs` не пуст) или переменная `T | undefined`. `Math.min()` и `Math.max()` без аргументов —
  ошибка.
- **`-0` остаётся:** он не ломает ни сравнения (`0 == -0`), ни расчёты.
- **Что получаем:** нет тихого `NaN`, который расходится по расчётам; `x == x` всегда, поэтому
  `sort` и ключи `Map` с дробными работают; `JSON.stringify` не пишет `null` вместо числа.
- **Скорость почти та же.** Замер clang -O3 против `-ffinite-math-only`: суммы, `sqrt`,
  деление, сравнения — без разницы; ×3 только в циклах `Math.min` по правилам JS и перевода в
  целое, где проверка `NaN` мешала векторизации. Операции с `double` получают флаги LLVM `nnan`
  и `ninf`.

## 11. Что уходит

| Было | Стало |
|---|---|
| `long` | `int` |
| `int` в 32 бита | `int32`, если нужны именно 32 |
| `int32 + int` и другое смешение типов | `a.toInt() + b` |
| неявный перевод целого в дробное | `n.toDouble()` |
| `x \| 0`, `x >>> 0` для заворота | `Bit.Wrap32`; для сужения — `.toInt32()` |
| `(x << n) \| (x >>> (32 - n))` | `Bit.rotateLeft32(x, n)` |
| `NaN`, `Infinity`, `isNaN`, `isFinite` | доказательство или `Result` |
| `let min = Infinity` | `Math.min(...xs)` или `T \| undefined` |
| предупреждения о переполнении | ошибки компиляции |

## План реализации

На каждом шаге: тесты `tests/run` (с `// same-as-node`, где поведение совпадает с JS), ошибки в
`tests/errors`, прогон с `-O0` и `-O2` под `TZ_CHECK_LEAKS=1`, обновление README. Это шаг 6
плана [errors.md](errors.md).

1. **Типы** (сделано 27 октября). `int` — 64 бита (в объектах — 8 байт), новые типы `int8` …
   `uint64`, `long` — ошибка с подсказкой, литералы подстраиваются под тип. До шагов 2 и 4
   узкие целые сами расширяются, а побитовые операции у `int` остаются 32-битными, как в JS.
2. **Явные приведения.** Операнды одного типа, тип результата — тип операндов, методы
   `toInt32()` и другие, сравнение разных целых по математике, целое с дробным — через
   `toDouble()`.
3. **Переполнение.** Ошибки вместо предупреждений ([small.md](small.md), раздел 6), диапазоны
   по вызовам, деление на 0 и `MIN / -1`, разбор не длиннее 64 бит, `buf[i]` — `uint8`.
4. **Биты.** Побитовые операции по ширине типа, ошибки на `| 0` и `>>> 0`, `Bit.Wrap32`,
   `Bit.Wrap64`, объект `Bit`. Переписать код с битами в `library/` и тестах.
5. **Без `NaN` и `Infinity`.** Диапазоны `double`, области определения `Math`, `Math.clamp`,
   `Result` у разбора и чтения дробных, флаги `nnan` и `ninf`.
